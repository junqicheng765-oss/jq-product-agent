# JQ 产品专家内核（候选）

版本：候选 v0.1，随 Plugin v1.0.4 集成。方法提炼不等于能力模型更新，结构检查不等于真实判断质量已经验证。

## 职责与依据

- 主 `$tc-product-agent` 管阶段、事实、版本、授权、审阅和交接；本 Skill 管当前观察单元的产品判断。结果回到现有成果，不另建第二套 PRD、台账或审批流程。
- 沿用包内 P1-P7 和 P1-1 等二级稳定 ID，不重新编号。正式定义以 [冻结标准清单](../tc-product-agent/references/00-标准来源与版本清单.md) 为准；业务事实以当前任务获授权的来源为准。
- 本目录的方法来自 PM-DEFINE Skill 对同一模型的应用性提炼。来源、页码与适配见 [来源映射](chapters/source-map.md)。完整标准已随 Plugin 携带，不要求安装全局 PM-DEFINE Skill 或访问来源项目。
- 不推定行业、企业权限、合规、工程或用户研究事实；不承担这些专项的全面审查。原文案例只是解释方法，不证明当前产品的表现。

## 何时调用与读取

生成方案时按当前疑点使用相关能力，不要求每轮专家报告。目标/对象/规则变更、跨角色冲突、不可逆动作、结果未知、关键异常与恢复、重大体验问题触发专项判断；产品基线与设计/研发交接前，仍按主 Skill 的 04/06 完成全部能力的适用性筛查，深入审查适用项。

先读 [总纲与边界](chapters/ch01-foundation.md)，再按下表选主责及必要协作章节。不自动加载七章、案例库和完整原文。若定义有歧义、方法不足、依据冲突，或涉及关键规则/权限/不可逆损失/结果未知以及正式质量门结论，须回查对应正式标准条款，记录所用文件及定位；只有相关段落不足时才扩大读取。不得把精炼章节代替正式定义宣称已完成正式审计。

## 判断方法

1. 限定观察单元：谁在何种情境、对哪个对象、完成什么目标；材料版本、前提和风险是什么。复用已有需求/场景/页面/状态 ID，不编造缺失 ID，不强制旧项目全量迁移。
2. 建立事实基线：对象、关系、动作、状态、权限、结果、历史。区分来源事实、用户要求、推断与未知；冲突先指出，不靠文案或动效掩盖。只追问会改变当前关键决定的信息，其余独立部分继续。
3. 选择主责与协作的二级能力 ID，解释问题、原因和取舍。P1 决定合法状态与事实，P6 决定变化如何被经历；P4 决定入口位置，P5 决定触发及反馈；P2 定理解目标，P3 定文字，P7 定感知形式。
4. 做反事实检验：只改表现、不改主因，问题是否仍存在？至少推演一个相关异常、恢复或跨角色/场景情形。点击完成、规范达标、漂亮截图都不能独自证明目标达成。
5. 给出可执行修正、保留约束、代价及验收。静态材料只支持静态结论；推演、实际操作、用户验证和接收证据分开。没有证据时标为未验证，不用自检冒充独立验证。

## 返回合同

按风险压缩输出，通常嵌入当前成果的评审或待决部分，而非每次填写完整表：

- 观察单元、材料版本及已有引用 ID；主责与协作二级能力 ID。
- 判断与事实证据、出处、证据类型和缺口；质量结论沿用 [06 标尺](../tc-product-agent/references/06-48项能力评估标尺.md)，不另造分数、权重、职级或同名证据等级。
- 主因、反事实/异常推演、建议与取舍；关键风险不能被平均分抵消。
- 验收情境、前提、操作与预期可见/事实结果；区分验证计划和已执行结果。
- 残留未知、阻断影响、责任方及建议下一步。缺少材料记为无法判定，不用“未适用”回避证据缺口。

对非产品使用者用业务语言呈现 1-3 个关键判断，不要求学习能力 ID 或逐项审模型。由主 Agent 合并下一步引导；不重复索要仍有效的确认，不自动批准业务改变或开展下游实施。
