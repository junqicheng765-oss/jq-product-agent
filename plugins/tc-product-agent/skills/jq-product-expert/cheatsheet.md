# 决策速查

| 如果看到 | 先做什么 | 主责与原因 |
|---|---|---|
| 功能目标只剩收入或活跃 | 找真实用户、情境、目标及有效改变 | P1：经营指标不足以解释用户价值 |
| 同一对象的权限、状态或结果互相冲突 | 建立对象、关系、规则和历史基线 | P1：表面优化不能消除内核冲突 |
| 专业经验被直接写成强制规则 | 分类硬约束、偏好、经验、例外与未知，核实来源 | P1：领域知识需要转译与作用范围 |
| 用户看得懂字却误解后果 | 检查心智、预期、信任，复核真实规则 | P2 主责，P1/P3 协作 |
| 短词掩盖范围或最终性 | 对齐对象、动作、状态和结果，分层解释 | P3：命名应支持正确理解 |
| 功能很难找到 | 核对归属、分类、入口、定位和返回 | P4：位置和路径组织问题 |
| 找到功能却不知能点、如何做 | 检查操作线索、意图映射和即时反馈 | P5：行为闭环问题 |
| 点后无反馈或重复提交 | 区分动作接收与业务结果，给必要控制 | P5；持续等待由 P6 协作 |
| 等待、中断后无法继续 | 明确阶段、离开、保存、恢复和结果到达 | P6；状态合法性依赖 P1 |
| 超时就写失败并要求重试 | 先确认结果是否未知，再定查询与重试条件 | P1/P6：未知不等于失败 |
| 所有元素都很醒目 | 定义首要感知目标，重新分配形式强弱 | P7；风险重要性依赖 P1/P2 |
| 静音、大字或非颜色条件下丢失关键事实 | 验证替代通道、重排、非颜色线索与真实任务 | P7：包容性是任务可用条件 |
| 页面漂亮却让用户过度放心 | 核实事实与心理目标，再检查形式影响 | P2/P7：信任需与能力匹配 |
| 只有截图却要求完整产品判断 | 评审可见形式，列流程、规则及长期体验待验证 | 证据范围决定结论范围 |
| 要求用模型评职级或给官方分数 | 根据作品找能力证据，说明缺失等级与权重规则 | 原文没有完整官方评分体系 |
| 以品牌案例证明今天的界面 | 记录版本快照，核对当前一手材料 | 历史案例不能冒充当前事实 |

## 六条边界

- P1 决定状态事实，P6 决定用户怎样经历变化。
- P2 决定心理目标，P3 决定文字，P7 检查感官形式的实际影响。
- P4 管位置与路径，P5 管位置正确之后的操作与回应。
- P5 管即时闭环，P6 管持续和异步，P7 管通道、强度与品质。
- 七能力协同，不是七步流水线；七原则也不是七项等权评分。
- 商业、工程、法律等可能是实际约束，本模型不提供这些专业的完整判断。

## 输出前检查

说清观察单元、证据与假设；解释主因及协作；至少检查一个相关异常或反事实；给出改进取舍和可观察验收；分开已实测与计划。完整模型回验另见 [ch10](chapters/ch10-case-validation.md)。
