# P3 语义与表达

来源：PDF 第 92-123 页；P3 V1.0。六项二级能力见第 100-110 页。

正式依据：[包内 P3 定义与案例](../../tc-product-agent/references/standards/P3-semantics.md)。本章为应用性提炼；二级 ID 沿用主包索引。

## 核心认识

把产品价值及事实转换为用户熟悉、准确、易懂、一致、愿意阅读和接受的文字意义系统。准确是底线，还需同时检查易懂、语境适配、吸引与合理引导。表达有倾向不自动等于营销；必须保留真实条件、代价、风险与知情选择。

## 六项二级能力

### P3-1 产品概念命名能力

为价值、对象、能力、角色、分类和设置建立边界明确、指向准确、可识别、可扩展的名称。核查用户已有称呼、近义概念和熟悉词引起的错误类比。对象边界未定时先回 P1，不把命名当作包装或内部代号外露。

### P3-2 动作语义设计能力

表达对谁做什么、成立条件、范围及主要后果。区分删除、移除、归档及实际可恢复性；高风险行动前说明金额、期限、影响对象、通知范围或不可逆结果。选项需平行可比，避免“确定/继续”脱离上下文或弱化拒绝含义。

### P3-3 状态语义表达能力

说明状态归属、当前事实、结果、原因、影响、最终性与下一步。区别请求接收、处理、待外部确认与最终生效，保留部分成功和结果未知。不能只写“失败”而遗漏资金、保存成果、时限和可恢复性。

### P3-4 复杂信息转译能力

从复杂概念、专业规则、权限限制、空状态、错误和异常中识别当前判断必需的信息，按用户判断顺序进行语义映射、分层解释和修复指引。保留条件、例外、风险、因果及关键精度。不是简单换词，也不是展示全部协议或统一“请重试”。

### P3-5 产品语言一致性能力

先形成内部核心概念与正式含义，再与界面语言建立稳定可追溯映射，覆盖页面、通知、邮件、帮助、客服、终端、角色及版本。管理改名、废弃、迁移和语义债务。同义应稳定，真实不同概念不能强行同名；场景表达可不同而事实边界不变。

### P3-6 用户语境适配与表达吸引能力

根据专业背景、年龄、语言、文化、任务压力、环境和阅读习惯，选择用词、语气、密度、句式、节奏与叙述入口。先回应用户最关心的事，让信息愿意被读、能够被接受。避免用互联网俚语代表所有人，或用催促、稀缺和拟人化弱化真实风险。

## 表达检查表

| 检查 | 需要说明 |
|---|---|
| 概念 | 它是什么，与相似对象有何区别 |
| 行动前 | 作用对象、范围、条件、费用、期限、风险与可逆性 |
| 行动后 | 已发生/未发生/尚未知的事实，影响与下一步 |
| 复杂规则 | 当前关键事实直接说清，完整细节按需提供 |
| 跨渠道 | 同一事实是否有稳定名称和含义 |
| 当前语境 | 先说关切，表达精度、密度和语气与任务风险匹配 |

## 书中案例重构

**自动续费：** 相比公文式流程说明，用户更需要先知道续费日期、金额和取消权，再按需读取完整规则。实际应用填写已确认日期与金额，不复用书中示例数字当真实规则。

**付款异常：** 只有确认资金未扣、订单仍有效且可安全重试时，才可以这样表达。若资金结果未知，不能为了清楚而写“未扣款”。先向 P1/P6 核实事实，再写对应语义。

## 相邻边界与反模式

- P1 定义事实；P2 定义理解及心理目标；P3 选择文字表达；P4 组织位置；P7 判断文字外观和非文字语义。
- 状态表达解释当前事实与直接原因；复杂转译说明复杂规则、限制和修复路径。
- 正式概念命名与当前语境措辞分别承担稳定概念和情境调整。
- 不用严谨长句证明专业，不用极短文字省略后果，不用品牌语气替代准确结果。
