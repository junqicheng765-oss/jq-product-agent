# B 方案与整体结构

以关键目标与边界已有有效依据的 A 阶段范围和当前事实源为输入；合并 A/B 审阅时未决部分仅为方案草稿。按主包 `references/05-复杂系统产品设计规程.md`、相关 P1 正式标准与 `references/07-阶段质量门与交付验收.md` 处理；本 Skill 不另立产品事实源。
产出格式按主包 `references/23-AF阶段产物模板.md` 的 B 节裁剪。


每次成果回复的第一行按主包 [流程导航与按需确认](../tc-product-agent/references/27-流程导航与按需确认.md) 展示主线第几步/共六步、当前具体步骤与真实状态；已有阶段内清单时附子步骤位置。不得只在阶段切换、过程消息或文件中展示。切换与收口由 Agent 核对必要产物和证据，交代下一动作及负责人；只为尚未解决的关键决定请人判断，已有有效依据不重审。需要使用者回答时，按同一规范的 Question 交互合同实际弹出原生问题；有建议时提供“按建议继续”等选项，不能只在结尾要求文字回复。
## 输入与判断

- 输入：A 的版本、目标用户与任务、约束、相关现状及冲突、可用的来源领域事实。
- 比较有实际差异的方案，说明价值、代价与舍弃项；不要为凑选项编造方案。
- 定义主要角色、业务对象、对象关系、模块职责、端到端主流程和外部边界。权限、状态、异步、迁移或跨模块依赖有高风险时，展开相应结构与可行性疑问；技术反馈不能替业务负责人决定业务规则。

## 产出与通过条件

产出可审阅的整体方案与结构图/表，列明关键业务决定、现状影响、风险和待决。判断者应能复述系统将怎样运转、谁负责什么，以及本轮没有覆盖什么。

关键结构和业务取舍足以支撑代表场景、所依赖决定有有效输入/确认或明确委托依据，且阶段检查通过后进入 C；新的重大方案取舍请人判断，已有效决定不因整理版本重审。未核实的行业规则或技术能力保持待决，并标影响范围和责任方。
