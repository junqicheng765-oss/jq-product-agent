# JQ Demo Quality

本 Skill 随 JQ Product Agent 一起安装。它只处理已明确范围的 Demo 制作与质检，不创建新的业务事实；产品主线、确认门、唯一事实源和交付状态以同包 `$tc-product-agent` 为准。独立调用时先取得当前有效的范围、Use Case、规则、体验约束和原型目标；缺少关键内容时指出缺口，不自造默认答案。

## Demo 宗旨

D/E 阶段交付的 Demo 打开后应直接呈现目标用户在相应使用端会看到、会操作的产品界面和任务。所有用户可见内容都按最终产品的使用情境写和呈现，包括标题、菜单、按钮、字段、预置记录、提示、空态、错误、通知、帮助内容与视觉元素；使用者应能以目标角色的身份完成任务，而不是被当作评审者听方案讲解。不得以项目介绍、设计理念、功能清单、流程解说、评审导航或操作教学充当 Demo 首页或主任务界面，也不得在产品文案中出现“这是 Demo”“点击这里体验”“此功能仅供演示”等面向评审的元叙述。只有当引导/帮助本身属于已定义的产品功能时，才放入用户界面。

可用合理的虚构数据与模拟行为支撑体验，不为提醒评审者而在产品画面加入“模拟/示例/演示”标签。运行前提、覆盖范围和未接入项只在交付记录中供制作与交接核对，不作为 Demo 的用户内容；Demo 已向观看者说明的事实不需要在界面里重复声明。可操作 Demo 仍不等于真实系统集成、最终视觉稿或生产实现。C 阶段的低成本结构骨架可用于讨论，不以它冒充 D/E 的用户可见 Demo。

## 路由

- 结构层：验证角色、对象、菜单/入口和页面职责，先用低成本骨架表达，不急于画完全部页面。
- 视觉方向层：根据使用场景、内容密度、已有品牌/设计系统和使用端，提出少量可比较的方向及理由；先做一张代表页面，确定信息层级、排版、颜色、组件和状态表达，不预设固定风格。
- 代表链路层：在认可的视觉方向上只打通一条高价值端到端任务；核对前置数据、操作、状态变化、成功/失败或结果未知、返回去向。
- 模块扩展层：基于已认可结构和组件扩展关键分支、异常、空态、等待、无权限、长文本与窄屏。新页面补整页；已有页面优先局部精修。
- 文案与交互复核层：制作后、展示与交付前必须读取并执行 [专项复核](../tc-product-agent/references/24-Demo文案与交互复核.md)，按当前交付范围使用同包 `$jq-product-expert`，留下覆盖、发现与复验记录，不以布局或主流程检查代替。
- 视觉复核层：在真实业务场景下检查信息主次、内容密度、间距与对齐、对比度、术语与控件一致、可用性和响应式。业务系统以可扫描、可重复操作为主，不把营销页视觉套路套入后台工具。

## 执行与证据

1. 先读取产品事实源、当前判断门和已有 Demo/设计证据，确定本轮只改变哪些页面、状态或视觉问题。
2. 列出本轮目标场景及覆盖，说明未覆盖项；原型工具与文件修改需要当前任务的真实授权。视觉方向不清楚时让使用者选择可见差异，不能让其逐个调整微小样式。
3. 先产出一张目标用户可见的代表页面，再制作可打开、可操作的链路；首次打开直接落在该角色的实际入口或任务场景。优先复用已有设计系统与组件。无可用工具时交同规格任务包，状态保持“待制作”。
4. 在桌面和窄屏实际打开检查，逐条走代表链路和必要异常；检查首屏、各状态及全程文案是否都站在目标用户视角，以及角色、前置数据、入口、操作反馈、状态、返回、相邻内容影响。若只能阅读说明或观看静态展示、无法完成代表任务，或界面持续向评审者解释方案，不判为合格 Demo。静态截图只证明静态画面，不代替交互验证。
5. 按专项复核检查当前范围的全部用户可见产品文案及关键交互，将反馈按结构、行为、内容、视觉归类，合并同类修改并复验受影响项；影响业务规则的冲突返回产品主线裁决，不在 Demo 中静默改规则。完整 Demo 交付覆盖全部交付范围；日常变更增量回归，不每轮重跑全模型。
6. 回传 Demo 版本/入口、Use Case 与状态覆盖；分别报告文案复核和交互复核的状态、证据、未覆盖与残留问题，再给人需确认的可见体验及下一步。缺少关键交互动态证据或有阻断时不得称对应范围通过；不称文案已是“最好”，不称视觉变好就等于产品正确或研发可实施。

外部设计 Skill 可以辅助视觉方向、制作与局部精修，但须先确认其来源、版本、运行依赖、权限及与当前设计基线是否兼容；其建议只作为待核对意见，不自动覆盖产品事实或触发安装、下载和钩子。多个视觉 Skill 不并行争夺同一页面的风格裁决。
