# F 详细规格与交接

按主包 `references/02-产出物与交接规范.md`、`references/06-48项能力评估标尺.md`、`references/15-设计交付与Figma回传规范.md` 和 `references/16-研发交付与实现验收规范.md` 工作；不另造 PRD 模板或技术事实。
模块 PRD 与交接索引按主包 `references/23-AF阶段产物模板.md` 的 F 节展开，具体字段仍以 `02/15/16` 为准。

## 输入与展开

- 输入：已确认的 A–E 范围、对象规则、Use Case、Demo 页面/状态、设计回传、迭代现状及未决项。
- 将已确认事实直接引用，既有规则可推导的细节由 Agent 展开并自检；新的业务取舍、权限责任变化和重大范围冲突交给人；证据不足或可行性问题保留待决并明确责任人。
- 输出模块 PRD、系统总览、需求—Use Case—页面/状态—验收映射、设计输入和研发交接清单；简单需求可合并文档，复杂系统按模块拆分，但产品规则只维护一处。

## 审计与通过条件

生成中按风险调用相关产品能力；形成基线和交接前对七类/48 项做适用性筛查，适用项有证据或待决，不适用项有理由。逐项核对主/异常/恢复路径、对象状态、权限、信息字段、界面行为、可测试验收及版本引用；不能用完整篇幅代替可实施性。

形成设计/研发交接候选时，按主包 `references/07-阶段质量门与交付验收.md` 的“F 阶段最小交付一致性核对”检查断开的 ID 引用、关键需求的直接验收关联和材料版本。复用已有映射、版本清单及文件摘要；把通过、问题、无法判定与不适用分别记到既有评审或交付说明，不为检查另造业务规则或要求新机器格式。冻结快照与现行来源分开判断；机械通过不代替 48 项审计、动态验证、人审或接收。

使用者只需决定新增业务判断、重大冲突和交付边界，不需逐字段改写。分别报告草稿/自检、人工确认、实际发送、设计或研发接收和实现验证；只有真实证据支持的状态才能标完成。
