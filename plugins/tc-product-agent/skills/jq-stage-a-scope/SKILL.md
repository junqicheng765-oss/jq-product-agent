# A 问题与范围

由 `$tc-product-agent` 维护唯一事实源与确认状态。本 Skill 只产出 A 阶段成果；按主包 `references/03-首轮澄清与审阅模板.md` 收集基础条件，存量迭代再按 `references/17-存量项目输入来源清单与冲突扫描.md` 核对本次影响范围。路径相对同包 `skills/tc-product-agent/`。
产出格式按主包 `references/23-AF阶段产物模板.md` 的 A 节裁剪，不另建平行事实源。


阶段切换与收口按主包 [流程导航与按需确认](../tc-product-agent/references/27-流程导航与按需确认.md)：由 Agent 核对必要产物和证据，交代当前位置、下一动作及负责人；只为尚未解决的关键决定请人判断，已有有效依据不重审。
## 输入与判断

- 输入：使用者原始想法、已知业务目标、用户和场景、端与首发优先级、约束、体验偏好；迭代时还需相关现状及来源。
- 区分已知事实、使用者意图、假设和 Agent 建议；不把同事尚未确定的目标或既有系统规则补成事实。
- 方向或任务不清时，按 [场景卡规范](../tc-product-agent/references/14-代表场景与Use-Case规范.md) 从已有输入提出候选，让人选择、补充或纠正；把角色、触发、目标、动作与结果说具体，未知项标明。输入已清楚则直接整理，不强制选卡或重复确认；场景审阅并入问题/范围审阅，C 沿用 ID 展开。
- 只追问会改变问题定义或首期边界的缺口；小需求允许与 B 联合审阅，但保留 A 的判断结果。

## 产出与通过条件

产出一份可审阅的问题与范围：问题、目标用户与任务、成功判断、首期内外范围、硬约束、待决项；迭代补相关现状、版本和冲突。给出取舍理由及需要使用者判断的事项。

核心目标和边界可解释、阻断性现状冲突已解决或明确限定，且关键范围已有明确用户输入、有效确认或明确委托依据，检查通过后可进入 B，不为整理成新文件重复批准。需要新的范围取舍时请人判断；A/B 合并审阅前可准备标明依赖的方案草稿。材料写出或 Agent 自检不等于用户确认。向 B 交付有效版本与未决项，不重写另一套事实。
