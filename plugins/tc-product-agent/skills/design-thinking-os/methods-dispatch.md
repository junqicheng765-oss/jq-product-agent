# 方法调度

输入：[methods-routing.md](methods-routing.md) 形成的产出合同、目标决定、决定工作集、证据动作集、最终设计起点和风险深度。  
目标：组装刚好够完成本轮任务的方法工作包，不跑固定流水线。

## 调度原则

1. 对决定工作集，从最终设计起点对应的未解决决定中选择形成方案的方法。
2. 对证据动作集，按待验证判断选择 PROTO/VAL/回归/对照方法；不在测试前重开 `TEST_INPUT`。
3. 再用设计语境卡筛选：用户能力、心智模型、情境、任务风险、信息、品牌和技术现实会改变方法参数或增加必要方法。
4. 只有某方法的最低输入满足时才调用；不满足且会改变结果时，先调用补输入的方法。
5. 一个未知不影响本轮产出时，不为它扩大范围。
6. 方法可以跨库组合，但每个方法都要回答一个明确问题。
7. “做完整套”不是理由；直接制作也必须有验收方法。

决定工作集为空但存在制作动作时，不强行选择设计方法；直接按动作合同应用已确认来源，再按证据动作执行成品后验收。方法自身命中“跳过”条件时不得为了形式调用。

同一个决定不能只靠 ID 调度。例如 D6 的普通扫读问题可用信息分级；高后果金融判断还必须覆盖内容、信任、精度和错误保护。语境要求必须进入工作包，不得停留在用户画像描述里。

若 D1–D9 扫描暴露出 N2 语境卡缺口，先返回 [methods-context.md](methods-context.md) 对应方法补齐，再选择下游设计方法；不从人口属性或行业标签直接派发 UI/视觉方法。

## 竞品跨决定调度

竞品方法不是固定前置，但其触发问题成立时，不受“只列在某个 D 下”限制：

- `CMP1 行业竞品`：D1–D9 任一决定需要类别门槛、替代方案、行业信任模式或差异机会时加入。
- `CMP2 同类操作竞品`：D4–D6、D8 或 D9 需要比较相同操作的流程、反馈、异常、恢复或验证方式时加入。
- `CMP3 服务同类用户的竞品`：D2、D4–D8 需要理解目标行为群体已经形成的语言、信息、导航、反馈或视觉习惯时加入；必须有用户—产品关系证据或明确标为待验证候选。

三类均为可选：现有材料或项目内部模式足够时跳过，并写复用依据。

## 决定 → 方法索引

### D1 问题与价值

可选：

- `CMP1 行业竞品`：需要理解类别门槛、替代方案和差异机会。
- `R0 现有证据审计`：先判断数据、反馈和旧研究能回答什么。
- `R1 问题卡`：不知道要解决哪件事。
- `R6 洞察归纳`：已有材料但尚未形成问题判断。
- `R8 价值主张与关键行为`：需要界定价值是否发生。

不要自动调用访谈；若现有材料足够回答当前问题，直接归纳。

### D2 用户与情境

可选：

- `CT2 行为群体与能力模型`：上游只有人口或角色标签，尚不能指导设计。
- `CT3 项目上下文与内部复用`：大项目内部哪些对象、模式、组件和资产可复用或扩展。
- `CMP3 服务同类用户的竞品`：需要基于真实用户—产品关系判断应保留、适配、教学或避免哪些习惯。
- `CT4 使用情境与任务重建`：设备、注意力、中断或参与者会改变设计。
- `R2 行为分群`：不同用户是否需要不同设计响应。
- `R3 情境访谈`：真实步骤、动机或判断标准未知。
- `R4 观察`：用户说不清，或说法和行为可能冲突。
- `R5 同理心地图`：已有跨来源材料，需要组织“想/说/做/看到”的矛盾。

同理心地图是综合工具，不是任何页面优化的默认前置。

### D3 用户/产品结果与成功指标

可选：

- `R1 问题卡`中的可观察成功标准。
- `R7 危险假设`：需要决定先验证哪个不确定性。
- `R8 关键行为与反指标`：要判断价值、转化或留存。

### D4 任务流程与范围

可选：

- `CT3 项目上下文与内部复用`：存量项目的上下游流程、共享对象或跨模块连续性会受影响。
- `CMP2 同类操作竞品`：需要比较相同操作的步骤、状态、反馈和恢复模式。
- `CT8 技术、数据与运营现实`：实际能力、延迟或持续供给会改变流程和范围。
- `F1 范围表`
- `F2 场景卡`
- `F3 主路径`
- `F4 干预点与概念`
- `F5 三档深度`

只改局部步骤时，可以只调用 F3 的受影响段，不重写整条路径。

### D5 交互规则、语义反馈与状态

可选：

- `CT3 项目上下文与内部复用`：需复用或扩展现有导航、反馈、错误、凭证和权限语义。
- `CMP2 同类操作竞品`：现有项目没有适用模式，需要跨行业比较操作原理和失效条件。
- `CT8 技术、数据与运营现实`：权限、异步、部分成功或结果未知尚未形成状态要求。
- `I1 步骤切页`
- `I2 命名与进出`
- `I3 页面职责`
- `I4 结构线框`
- `I5 主行动反馈`
- `I6 异常矩阵`

若页面职责已确认，只修一个错误反馈，直接调用 I5/I6。

### D6 UI 信息层级与内容

可选：

- `CT3 项目上下文与内部复用`：需判断已有术语、内容模板和组件是复用、扩展还是新建。
- `CMP2 同类操作竞品`：需要比较组件、状态与反馈背后的操作条件，而非外观。
- `CMP3 服务同类用户的竞品`：需要判断目标群体已学会的信息、术语和操作习惯。
- `CT5 后果、风险与信任模型`：高后果判断尚未形成信息、预防和恢复要求。
- `CT6 信息与理解要求`：用户做决定前必须理解什么尚不清楚。
- `U0 UI 落地前置分流（存量延展 / 纯 B 端公开组件库快搭 / C 端 0→1 视觉决策）`
- `U1 最少信息分级`
- `U2 单一主行动`
- `U3 对比/亲密/对齐/重复`
- `U4 组件`
- `U7 对象表现形式与尺寸分级`：界面里有用户在现实或该领域里认得的对象（卡牌、票据、商品、地图、文件、角色等）时必用。
- `U5 状态`
- `U6 界面文案`

UI 方法不能替代未解决的流程或交互决定。进入视觉落地前先通过 `U0` 判断：有现成页面直接走存量延展；0→1 纯 B 端直接连接公开组件库（`Ant Design` / `Arco Design` / `TDesign` / `shadcn/ui` / `MUI` / `Fluent UI`）快搭；0→1 C 端进入 `V0` 风格库与 6 维视觉决策。

### D7 UI 界面视觉系统与资产

可选：

- `CT3 项目上下文与内部复用`：需核对设计系统、共享组件、变量和资产的复用范围与授权。
- `CMP3 服务同类用户的竞品`：有真实使用证据时，用于理解已培养的密度、语言和反馈习惯；不得据此复制品牌风格。
- `CT7 感知目标与品牌角色`：只有“专业、高级、年轻”等抽象词，尚不能形成视觉边界。
- `V0 0→1 视觉风格库与 6 维决策漏斗`：C 端或强品牌产品从 0 到 1 时，按风格池与行业严肃度剪枝；语境明确时 Agent 直接定风格并自动配齐主色、底色、容器材质、圆角、字体密度、图标风格，方向高度开放时才用大白话问 1 个大方向问题。
- `V1 视觉依据`
- `V2 语义色`
- `V3 字体与密度`
- `V4 气质句`
- `V5 图标与图片`
- `V6 同结构候选比较`
- `V7 图片生成双路径协议`：UI 界面内配图由 Codex / Agent 操作 Figma 原位生成；独立海报/运营图/KV 走「图文角色判断 → 版面结构草图 → 搜直观风格参考垫图 → 双图同垫生图」。

有正式设计系统或现成相关页面时优先引用，不重新生成风格方向；纯 B 端 0→1 优先绑定公开组件库快搭。D7 属于 Figma UI 正式主稿，不是自动调用外部视觉工具的后续阶段。界面中的插画、图片、图标和品牌图形仍由 Figma UI 负责（可通过 Figma 原位生图完成）；只有最终交付本身是非界面视觉成品（如运营海报/KV）或用户明确拆分的独立视觉委托时，才按 [methods-tool-routing.md](methods-tool-routing.md) `TR4` 与 `V7 路径 B` 建立视觉工具动作。

### D8 UI 动效表达

可选：

- `M1 反馈动效`
- `M2 状态转换`
- `M3 空间关系`

M1–M3 只服务 UI 反馈、状态转换和空间关系。静态状态已足够表达时可以不做动效。确需进入 D8 时，最低输入必须包含已定稿 UI（Figma 节点或 HTML/代码页面）的准确版本、稳定对象/状态标识，已确认 D5 规则，以及正式动效基线或探索授权（用户委托做设计即默认授权，见 [methods-motion.md](methods-motion.md) 入口门）。探索授权不能绕过已定稿 UI 或 D5。UI 或 D5 可由本轮设计补齐时先补齐；只有必须由外部事实或授权解决时才在 N4 标 `BLOCKED/WAIT_EXTERNAL`，不派发 M 方法。

动效实现按三路分流：
1. **UI 交互动效（`TR5-A`）**：Figma 原型只可作为 `FIGMA_MOTION_PREVIEW`；正式交付必须通过写代码实现（CSS / JS / GSAP / 客户端代码）。
2. **复杂 3D / 光影 / 流体动态图与宣传视频（`TR5-B`）**：先确认首尾关键帧垫图，再调生视频模型，按场景转码为 `MP4` / `WebM` / `GIF` / `动态 WebP`（不得将视频像素序列帧伪装成矢量 Lottie）。
3. **轻量矢量动画（`TR5-C`）**：SVG、真 `Lottie (.json)`、图标微动效先从 IconScout 拿现成 Lottie / 动态图标，库里没有再基于专业矢量图标用代码加动画，不手画简陋图形，不调用生视频模型。后两类不默认调用 M1–M3；只有其中某段运动表达 UI 反馈、状态转换或空间关系时，才为该段关联 D8。

### D9 验收或验证程序

根据工作模式选：

存量项目若通过 CT3 复用、扩展或新增共享模式，D9 必须包含受影响模块、共享组件和上下游链路的回归范围；共享 `EXTEND/NEW` 未获责任人授权时保持 `BLOCKED`。

- 直接制作：规格一致性 + 范围核对。
- 局部优化：修改前后对比 + 受影响路径回归。
- 问题探索：假设证据 + 下一决策。
- 方案验证—验证准备：`PROTO1 测试就绪原型` + 本轮完整性验收 + `DEFERRED_NEXT_ROUTE` 合同；不运行 VAL、不更新被测决定。
- 方案验证—验证执行：`VAL1 概念理解` / `VAL2 任务走查` / `VAL3 内容与信任` / `VAL4 人工价值交付`。
- 设计还原/交付：主稿逐项对照 + 动态行为验证。

VAL1–VAL3 需要用户阅读、判断或操作方案时，先调用 `PROTO1 测试就绪原型`；已有同版本且预测试通过的载体可复用。VAL2 还必须具备被测主路径、D5 反馈与关键失败分支，不能用点击热区替代。

具体见 [methods-close.md](methods-close.md)。

## 最低补输入规则

若选中方法缺最低输入：

- 缺用户方才有的主稿文件或素材（Logo、真实产品图、真实数据等）：标 `BLOCKED/WAIT_EXTERNAL` 并问人，不用占位或自行降级。
- 缺通用素材（图标、3D、插画、背景、虚构角色头像）：从 IconScout 获取或 AI 生成，不问人。
- 缺业务取舍：给有代价的选项，请人决定。
- 缺用户证据但可安全探索：标 `ASSUMPTION:`，给最小补证，不阻塞草案。
- 缺上游决定且可由设计工作解决：标 `MISSING/RESOLVE_NOW`，回到该决定。
- 缺上游决定且必须由外部授权或事实解决：标 `BLOCKED/WAIT_EXTERNAL`，不得用下游方法掩盖。
