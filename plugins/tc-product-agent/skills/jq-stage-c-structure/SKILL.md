# C 场景与结构原型

以有效的 A/B 版本为依据，按主包 `references/14-代表场景与Use-Case规范.md` 生成场景；原型的结构与可见行为同时受 `$jq-demo-quality` 约束。不要把样本项目的菜单或对象带入调用者项目。
产出格式按主包 `references/23-AF阶段产物模板.md` 的 C 节裁剪。


每次成果回复的第一行按主包 [流程导航与按需确认](../tc-product-agent/references/27-流程导航与按需确认.md) 展示主线第几步/共六步、当前具体步骤与真实状态；已有阶段内清单时附子步骤位置。不得只在阶段切换、过程消息或文件中展示。切换与收口由 Agent 核对必要产物和证据，交代下一动作及负责人；只为尚未解决的关键决定请人判断，已有有效依据不重审。需要使用者回答时，按同一规范的 Question 交互合同实际弹出原生问题；有建议时提供“按建议继续”等选项，不能只在结尾要求文字回复。
## 输入与判断

- 输入：用户任务、角色/对象/模块、主流程、首发边界、当前有效产品事实及体验约束。
- 首次制作实际结构原型前，按 [设计能力初始化与复用](../tc-product-agent/references/26-设计能力初始化与复用.md) 明确制作路线并展示设计准备结果；路线未回答时可继续文字场景、流程和页面职责分析，不直接画页面。已有选择或明确委托直接复用。
- 若要制作或修改存量系统的结构原型，先按 [设计能力初始化与复用 §5](../tc-product-agent/references/26-设计能力初始化与复用.md#5-存量迭代的现状界面条件) 取得有效 Figma、截图或可访问现状页面；有效资料直接沿用，缺失时只做不依赖界面的场景/流程分析，不凭文字重画现状。
- 复用 A/B 的场景与确认，按 `14` 选择业务全链路或功能级用例；复杂系统先以真实业务生命周期连接模块，再加深高风险功能，不套项目管理步骤或固定步数。缺方向时才给候选卡，明确输入直接展开；用已有 ID 反查目标、角色、首期范围和功能，逐步连接页面/状态与验收，不重复建覆盖表。
- 再安排入口、菜单、页面职责与返回关系；存在结构取舍时按 [产品类型设计基线](../tc-product-agent/references/25-产品类型设计基线.md) 选择主骨架与叠加约束，理由并入当前成果；只在必要时画低成本结构原型。
- 结构原型用于判断“能否找到、是否理解、页面各自负责什么”，不把未做出的交互和隐藏规则标为已确认。

## 产出与通过条件

产出用户视角 Use Case、入口/菜单和关键页面骨架、Use Case—页面覆盖清单、未覆盖项及结构取舍。核对主要角色能从入口走向任务，不存在明显断层或重复职责。

代表场景与信息结构的重大遗漏已处理、关键结构决定有有效确认或明确委托依据，检查通过后进入 D。关键体验尚需实际操作才能判断时，可与 D 的代表链路合并展示，结构仍标候选；依赖未定重大结构的全量制作暂缓，不为每个场景/页面单独确认。小需求可与 D/E 合并展示，保留判断依据。
