# C 场景与结构原型

以有效的 A/B 版本为依据，按主包 `references/14-代表场景与Use-Case规范.md` 生成场景；原型的结构与可见行为同时受 `$jq-demo-quality` 约束。不要把样本项目的菜单或对象带入调用者项目。
产出格式按主包 `references/23-AF阶段产物模板.md` 的 C 节裁剪。

## 输入与判断

- 输入：用户任务、角色/对象/模块、主流程、首发边界、当前有效产品事实及体验约束。
- 先确定覆盖哪些代表性 Use Case，再安排入口、菜单、页面职责与返回关系；只在必要时画低成本结构原型。
- 结构原型用于判断“能否找到、是否理解、页面各自负责什么”，不把未做出的交互和隐藏规则标为已确认。

## 产出与通过条件

产出用户视角 Use Case、入口/菜单和关键页面骨架、Use Case—页面覆盖清单、未覆盖项及结构取舍。核对主要角色能从入口走向任务，不存在明显断层或重复职责。

代表场景与信息结构的重大遗漏已处理、该范围获确认，才进入 D 的可操作链路制作。小需求可与 D/E 合并展示，但结构判断仍需可追溯。
