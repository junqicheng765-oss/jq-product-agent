# E 模块展开与体验收敛

沿用已确认的 D 行为、页面结构和有效产品规则，使用 `$jq-demo-quality` 核对结构、行为、状态及视觉。D 的轻量视觉方向不是最终设计确认。不要因审阅意见重画全部页面；既有页面优先局部精修，新页面才补整页。
产出格式按主包 `references/23-AF阶段产物模板.md` 的 E 节裁剪。


每次成果回复的第一行按主包 [流程导航与按需确认](../tc-product-agent/references/27-流程导航与按需确认.md) 展示主线第几步/共六步、当前具体步骤与真实状态；已有阶段内清单时附子步骤位置。不得只在阶段切换、过程消息或文件中展示。切换与收口由 Agent 核对必要产物和证据，交代下一动作及负责人；只为尚未解决的关键决定请人判断，已有有效依据不重审。
## 输入与制作

- 输入：A–D 有效版本、模块依赖与风险、代表 Demo、用户反馈、未覆盖 Use Case/状态、设计工具与授权。
- 复用 [设计能力配置](../tc-product-agent/references/26-设计能力初始化与复用.md) 的有效连接、用户指定目标及边界，只核对变化。存量迭代扩展/修改原型时先补足相关现状界面参考；沿用 D 的有效参考，不重复收集，不把资料缺口当作自由改版许可。
- 按跨模块关系、权限/金额/状态风险、使用频率和依赖顺序选择扩展范围；简单需求可与 C/D 联合审阅。
- 按 [产品类型设计基线](../tc-product-agent/references/25-产品类型设计基线.md) 沿用 C/D 的主骨架与叠加约束；新增模块若任务不同，可有局部骨架但保持共享语义/组件一致。将基线及场景、品牌/组件依据传入设计任务包，三套候选保持相同内容和行为。用代表页面/状态验证取舍，不因分类、风格名称或视觉评分就称体验已通过。
- 一轮反馈先归类为业务规则、任务流程、内容结构或视觉细节，合并同类问题。局部视觉精修按需使用已随包安装的 `$impeccable`；其审阅报告和产品能力审计重叠时合并为一条问题，由主 Agent 判主责，不形成两轮重复批准。
- 行为与状态覆盖确认后，按 [设计交付规范](../tc-product-agent/references/15-设计交付与Figma回传规范.md) 选择 Figma 完整、部分或 Codex 路线。无既定视觉基线时，产品 Agent 从任务、品牌约束和信息密度生成三套同页面风格任务；人选定后再扩全范围页面/状态。已有设计系统的迭代优先复用，不擅自改品牌。
- 所有路线均执行上述规范 §2.1：展示真实候选画面并记录选择，或记录既有基线的沿用依据；明确委托 AI 决策时记录委托范围及选择理由。不因采用 Codex、已有临时样式或通过文案/交互检查而省略。尚在行为扩展时，交付回复说明风格仍未选定、触发条件和下一产物；不要求用户提前理解内部阶段。
- Figma 路线按设计交付规范 §2.2 逐页分流：已有可编辑页面优先 Computer Use 直接改图层/组件，不必先调用 Figma Agent；新增或缺失整页由 Figma Agent 按现有风格/组件生成，再用 Computer Use 精修。同一需求可混用，两步串行；新页面不自动触发三套新风格。回审后读取准确 Frame 的上下文、截图与素材，还原有样式 Demo。实际写入前通过 [执行前核对卡](../tc-product-agent/references/18-Figma执行前核对卡.md)；仅缺 Agent 不阻断已具备条件的旧页编辑，其他缺项按受影响范围处理，不伪称已完成。

## 产出与通过条件

交付扩展后的可操作 Demo、模块/场景/状态覆盖、所选视觉方向、设计回传或本地视觉证据、设计还原的有样式 Demo、变更及未覆盖清单。实际检查相邻页面、全局入口、关键异常、空/载入/错误/无权限、长文本和窄屏；未执行的状态不得宣称对齐。

展示扩展模块及完整交付前，自动执行 [Demo 文案与交互复核](../tc-product-agent/references/24-Demo文案与交互复核.md)，补齐本次范围的文案和交互覆盖、修正与复验记录；完整 Demo 交付必须覆盖全部交付范围，变更只回归受影响项及共享语义/行为。关键交互缺动态证据或阻断/重大问题未关闭时不标对应范围通过。

当可见体验和已知业务规则足以支持详细规格、对应范围专项复核条件满足、重大冲突已处理且未决项有归属，且重要体验与视觉取舍已有有效确认或明确委托依据后，进入 F；普通状态补齐和授权内精修自检通过后继续，不逐模块/控件另设批准。所有路线记录风格选择或沿用依据；缺失时不能把该范围 E 或最终有样式交付标为完成，不依赖视觉的 PRD 草案可继续准备。Figma 路线分别记录设计链接可读、设计稿已确认、代码还原已验证；Codex 路线记录本地视觉产物及 Demo 验证，明确无 Figma 稿。生成、静态验收、动态验证和用户确认分别记录。
