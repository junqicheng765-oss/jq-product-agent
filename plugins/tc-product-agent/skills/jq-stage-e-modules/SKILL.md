# E 模块展开与体验收敛

沿用已确认的 D 视觉方向、页面组件和有效产品规则，使用 `$jq-demo-quality` 核对结构、行为、状态及视觉。不要因审阅意见重画全部页面；既有页面优先局部精修，新页面才补整页。
产出格式按主包 `references/23-AF阶段产物模板.md` 的 E 节裁剪。

## 输入与制作

- 输入：A–D 有效版本、模块依赖与风险、代表 Demo、用户反馈、未覆盖 Use Case/状态、设计工具与授权。
- 按跨模块关系、权限/金额/状态风险、使用频率和依赖顺序选择扩展范围；简单需求可与 C/D 联合审阅。
- 一轮反馈先归类为业务规则、任务流程、内容结构或视觉细节，合并同类问题。局部视觉精修按需使用已随包安装的 `$impeccable`；其审阅报告和产品能力审计重叠时合并为一条问题，由主 Agent 判主责，不形成两轮重复批准。

## 产出与通过条件

交付扩展后的可操作 Demo、模块/场景/状态覆盖、统一视觉组件与设计任务输入、变更及未覆盖清单。实际检查相邻页面、全局入口、关键异常、空/载入/错误/无权限、长文本和窄屏；未执行的状态不得宣称对齐。

当可见体验和已知业务规则足以支持详细规格、重大冲突已处理且未决项有归属，并获得该范围确认后，进入 F。生成、静态验收、动态验证和用户确认分别记录。
