# 能力运行定义与边界

版本：v0.4｜用途：让 Subagent 在评审中知道“当前问题应由哪项能力解决”，避免重复计分或用错误层面的方案修补问题

本文件将能力模型转成运行时可调用的定义。它不替代本 Skill `standards/` 中的完整正式文献、案例和版本治理；若出现冲突，以该目录的冻结正式定义为准。这里的目标是让独立运行的 Subagent 仍能正确分责、提出判断和保留证据。

## P1 产品逻辑

**运行定义**：从用户价值和目标出发，建立对象、关系、状态、规则、约束、异常和演进方式一致的产品世界模型，使不同入口、角色和场景能推导出同一产品事实。

**应先解决**：对象到底是什么、谁拥有什么/能做什么、一次动作改变哪个事实、哪些例外仍成立。

**不替代**：页面路径、文案、信息结构、交互反馈或技术实现。若“取消”对什么对象生效尚未定义，先修 P1；不能用补按钮、改文案或加确认弹窗绕开。

| 二级能力 | 运行时的关键判断 |
| --- | --- |
| P1-1 价值及目标 | 能否从用户问题和场景解释为何需要该对象、规则或功能 |
| P1-2 领域转译 | 来源领域的目标、约束和例外是否有来源并保真进入产品模型 |
| P1-3 对象 | 是否定义稳定身份、职责、边界和生命周期，而非页面元素 |
| P1-4 关系 | 归属、参与、可见、拥有、引用和控制是否被区分并可变化 |
| P1-5 状态 | 状态属于哪个对象、何时变化、能否回退和如何保留历史 |
| P1-6 规则 | 角色、条件、优先级、限制和结果是否跨入口一致 |
| P1-7 异常 | 冲突、过期、失权、部分成功和撤销时共同规则如何延展 |
| P1-8 演进 | 新能力、历史数据和用户预期如何兼容、迁移或替代 |

## P2 认知与心理引导

**运行定义**：理解具体用户在任务中的心智模型、注意、记忆、判断、动机、预期、信任与心理状态，定义产品需要建立的理解和心理条件，使人以合理成本自主完成有价值的行为。

**应先解决**：用户会如何误解、害怕、过度相信或无法坚持；产品应让其知道什么、相信什么、保留什么选择。

**不替代**：P1 的事实定义，也不等于“文案更友好”或心理学话术。P2 定义心理目标，P3/P4/P5/P6/P7 分别通过语言、结构、操作、时间和感知实现它。

| 二级能力 | 运行时的关键判断 |
| --- | --- |
| P2-1 心智模型 | 新概念能否借助用户已有经验理解，哪些差异必须明确 |
| P2-2 认知负担 | 当前任务是否只要求用户承担必要的理解、记忆与选择 |
| P2-3 动机引导 | 是否存在真实价值、知情选择和拒绝/退出条件 |
| P2-4 预期信任 | 承诺、自动行为、权限、限制和结果是否与实际相称 |
| P2-5 迁移习惯 | 同类规律能否从一次成功迁移到新对象和新场景 |
| P2-6 心理状态 | 等待、失败、高压和不确定时是否仍保持掌控和可行动 |

## P3 语义与表达

**运行定义**：把已定义的产品概念、动作、状态、规则和复杂信息转为准确、可理解、与语境相称且跨触点一致的表达，使用户能据此判断和行动。

**应先解决**：同一个词是否只表示一个概念；动作和状态能否让用户理解范围、原因、结果及下一步。

**不替代**：P1 对事实的定义，P4 的信息归属，P7 的感知呈现。表达清晰不能修复概念本身含混，也不能只用颜色、图标或动效替代文字语义。

| 二级能力 | 运行时的关键判断 |
| --- | --- |
| P3-1 概念命名 | 名称是否稳定、准确且符合用户的真实语境 |
| P3-2 动作语义 | 动词是否准确表达作用对象、后果和可逆范围 |
| P3-3 状态表达 | 当前、历史、处理中、成功、失败和未知是否可区分 |
| P3-4 复杂转译 | 复杂规则/数据能否被转成用户可判断的信息 |
| P3-5 语言一致 | 页面、通知、帮助和跨端是否解释同一事实 |
| P3-6 语境适配 | 语气是否匹配角色、风险、场景和可行动需要 |

## P4 空间与结构

**运行定义**：把对象、信息、功能和任务路径组织为可发现、可定位、可跨空间连接且可随规模演进的结构，使用户在不同设备和入口中保持归属和方向。

**应先解决**：对象属于哪里、何时能找到、从哪里进入、如何回到正确上下文、跨端/跨角色如何不断链。

**不替代**：P1 的对象关系、P3 的文字含义、P5 的操作反馈。目录整齐或页面漂亮不等于结构正确。

| 二级能力 | 运行时的关键判断 |
| --- | --- |
| P4-1 对象组织 | 核心对象是否有稳定、可理解的归属位置 |
| P4-2 分组层级 | 分类是否反映任务和关系而非实现/视觉方便 |
| P4-3 跨设备排布 | 小屏、放大或换端后是否仍能理解并操作关键对象 |
| P4-4 入口发现 | 高频、低频和异常任务是否都能在需要时找到入口 |
| P4-5 定位返回 | 深链、筛选、失权和返回后是否保持或安全恢复上下文 |
| P4-6 跨空间路径 | 角色、端、系统之间的任务如何连续和回查 |
| P4-7 结构演进 | 规模、历史和新对象增长后如何保持稳定组织 |

## P5 交互与反馈

**运行定义**：让用户的意图能被清楚表达、系统条件和结果能被理解、错误和风险能被控制、操作后能恢复和回查，使行为形成可信闭环。

**应先解决**：用户如何表达意图、系统是否接收、真实结果是什么、错了如何修正或恢复。

**不替代**：P1 对“什么结果真实成立”的定义，P6 对异步过程的时间体验，P7 对反馈的感知形式。瞬时 Toast 不是完整反馈闭环。

| 二级能力 | 运行时的关键判断 |
| --- | --- |
| P5-1 意图映射 | 用户目标是否有直接、合适且语义明确的操作 |
| P5-2 操作理解 | 操作、条件、禁用原因和后果是否可发现/理解 |
| P5-3 反馈闭环 | 接收、处理、成功、失败和回查凭据是否分开呈现 |
| P5-4 控制恢复 | 可取消、修正、重试或恢复什么，边界是否真实 |
| P5-5 风险防护 | 高风险是否核对对象/影响，低风险是否避免过度打断 |
| P5-6 多路径一致 | 同一对象和动作在页面、消息、端和输入方式中是否同义 |
| P5-7 高频效率 | 高频优化是否同时保留检查、纠错和范围可见性 |

## P6 过程与状态

**运行定义**：设计用户对生命周期、变化、等待、中断、异步结果、失败和跨场景连续性的时间经历，使任务在不理想条件下仍可理解、可继续和可恢复。

**应先解决**：变化何时发生、用户等待什么、离开/返回后以什么为准、结果迟到/失败时如何继续。

**不替代**：P1 的状态归属和合法转换，P5 的一次操作反馈，P7 的视觉/声音/动效。进度条不等于过程设计，状态名称也不等于用户经历。

| 二级能力 | 运行时的关键判断 |
| --- | --- |
| P6-1 生命周期 | 阶段、终止、归档、恢复和责任如何被组织 |
| P6-2 变化理解 | 时间、主体、原因和优先级是否可追溯 |
| P6-3 等待进度 | 等待、可离开性、真实进展和下一步是否可判断 |
| P6-4 中断恢复 | 弱网、刷新、换端和暂停后如何避免重复与丢失 |
| P6-5 异步到达 | 延迟、乱序、去重、通知与当前对象如何一致 |
| P6-6 失败降级 | 超时、部分成功、失败和降级如何如实呈现和补救 |
| P6-7 连续性 | 长任务、跨场景、版本/权限变化后如何保持身份和上下文 |

## P7 感知体验设计

**运行定义**：以产品事实和认知心理目标为基线，定义重点、状态、风险、变化和品质应如何被可靠感知，并以层级、秩序、强度、通道、适配和整体气质验收体验。

**应先解决**：谁在何种情境必须先感知什么、哪些误判不可接受、不同设置/设备/环境如何仍成立。

**不替代**：P2 的心理目标、P3 的文字内容、P4 的组织关系、P5 的反馈机制、P6 的时间过程。它不要求产品 Subagent 制作视觉稿，也不能退化为个人审美偏好。

| 二级能力 | 运行时的关键判断 |
| --- | --- |
| P7-1 感知目标 | 用户、情境、必要事实、底线、反原则和验证方式是否明确 |
| P7-2 层级重点 | 风险、状态、结果和主任务的注意顺序是否相称 |
| P7-3 一致秩序 | 同义线索是否稳定、异义线索是否可分且覆盖异常/跨端 |
| P7-4 心理影响 | 强度、密度、节奏是否支持真实信任和自主判断 |
| P7-5 多感官反馈 | 视觉、声音、触觉、动效是否有分工、替代、控制和降级 |
| P7-6 包容可用 | 文字、颜色、键盘、放大、设置、环境和能力差异是否覆盖 |
| P7-7 品味品质 | 一致、克制、比例、节奏、细节与定位是否形成整体品质 |

## 使用顺序

先用本文件判断主责和相邻边界；再用 `04` 判断适用性、用 `06` 给出质量结论、用 `10` 选择代表任务和证据，最后在 `11` 汇总为可行动的评审结论。不要把能力名称本身当成证据。
