# 研发交付与实现验收规范

版本：v0.4｜用途：将产品基线、产品原型和有效设计输入交给研发与 QA，并使实现结论能回溯到原始产品判断。

## 1. 模块开发 PRD

进入研发的模块创建 `product/handoff/rd/RD-<模块>-开发PRD.md`。研发交接包同时引用当前产品定义、产品原型和已返回且有效的设计稿/设计引用；设计尚未返回时只能标为研发交接草案，并明确受影响范围。模块按“触发 → 输入 → 校验 → 处理 → 决定 → 状态变化 → 输出 → 恢复”拆分，不按页面或技术服务拆分。

必须包含：文档控制和上游版本；存量资料被采用时的来源清单/冲突处理状态；问题/目标/范围；模块 Use Case；角色、可见范围、操作权和决定权；入口、定位和返回；页面/组件索引；字段字典（来源、必填、默认、边界、校验、权限、影响）；业务输入输出；流程和状态迁移；`FR`、`BR`、`EC`；通知/待办/留痕；用户可观察的非功能要求；发布/迁移/回退；Given/When/Then `AC`；`Use Case → FR/BR/EC → 页面/设计证据 → AC` 追溯；开发就绪检查和未决项。

产品 PRD 不定义 API、数据库、服务架构、算法或部署。研发可选择实现方案，但不得改变产品规则。

## 2. 技术回传

研发实际审阅后，以 `RD-<模块>-技术回传.md` 返回：引用的产品/设计版本与条目、实际约束或依赖、影响对象和范围、可选方案及代价、是否阻断、需要谁裁决、已确认与未确认的技术事实。技术约束写入技术回传；若影响产品行为，由产品负责人更新 `01`/`04`，不能仅在聊天或代码注释中改变规则。

## 3. 实现验收追踪

开发、测试和产品验收期间维护 `RD-<模块>-实现验收追踪.md`：

| Use Case | FR/BR/EC | 设计页面/节点 | AC | 验证类型与证据 | 结论 | 未通过项/责任/恢复 |
| --- | --- | --- | --- | --- | --- | --- |
| SC/UC-xx | FR/BR/EC-xx | Figma 证据 | AC-xx | 产品推演/设计验证/实现测试 | 通过/条件通过/不通过 | Q-xx / 责任方 / 下一动作 |

必须分开记录产品推演、设计验证、实现验证和用户确认。实现通过不能证明长期用户价值；产品确认不能证明代码已实现。

## 4. 开发就绪与验收门

- 开发就绪：当前 PRD、可操作产品原型、有效设计状态、模块边界、输入输出、角色/权限、状态、异常恢复、验收与依赖可定位；不存在要求研发自行解释的并列方案或阻断缺口。
- 交接接收：材料已发出不等于接收；仅有真实接收或反馈时更新状态。
- 实现验收：结论可反查对应需求、设计和证据；失败、部分完成、结果未知和回退后的用户处理明确。
