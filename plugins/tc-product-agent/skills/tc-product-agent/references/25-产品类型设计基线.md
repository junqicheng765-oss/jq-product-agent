# 产品类型设计基线

版本：v0.1｜用途：在 C/D/E 根据真实任务选择结构、交互和感知方向，避免不同产品都套用一种后台或营销页样式。它是运行层的设计启发，不是新的能力模型、行业事实或合规标准。

## 1. 选择方法与优先关系

先读取本轮有效的用户、任务、业务对象、设备/环境、频率、信息密度、错误代价与既有设计系统。A/B 已有的信息直接复用；分类由 Agent 给出理由，不要求使用者先学会产品分类。关键情境未知且会改变设计时才补问。

选一个最能解释主要任务的**主骨架**，再叠加实际存在的风险、协作、内容或 AI 约束；同一产品不同空间可以有不同骨架，但同一对象和动作保持语义一致。混合场景不硬套唯一标签，也不因此维护几套平行规范。

可追溯业务事实、已确认规则与授权范围决定“做什么”；实际用户能力、使用端、风险和现行品牌/组件约束决定“怎样表达”。下表只是可调整的起点，冲突时回到具体任务和证据。既有规范若妨碍关键任务或可用性，提出问题和局部调整建议，不静默改品牌，也不因有规范就报通过。不能据产品类型编造审批、权限、功能或行业规则。

## 2. 按任务选择的基线

| 产品类型/情境 | 优先支持的任务 | 结构与表达起点 | 交互与复核重点（仅检查实际存在者） |
| --- | --- | --- | --- |
| 消费与生活服务 | 低学习成本地完成当前主要任务，常有移动、碎片时间或中断 | 突出当前动作和结果，必要信息渐进展开，语言贴近用户 | 输入负担、触控、提交后的下一步、中断后续做；不要把多层管理导航强加给用户 |
| 企业 SaaS/协作工作台 | 在多对象、多角色和责任范围间检索、处理与交接 | 可扫描的信息密度；按任务选列表、筛选、详情或工作区，明确对象和范围 | 批量影响、权限可见性、交接状态、筛选与返回上下文；不是所有企业界面都必须高密度表格 |
| 专业创作/生产工具 | 持续编辑对象、比较结果、提高熟练操作效率 | 任务需要时采用画布、对象树、属性面板或专业工作区；术语配情境帮助 | 选择范围、撤销/恢复、快捷操作的可发现性、保存与长任务状态；不以极简隐藏必要工具 |
| 数据/开发者/管理控制台 | 查询、诊断和执行有范围的管理动作 | 按问题组织查询、数据、日志与详情；保留口径、单位、时间与数据新鲜度 | 空数据与查询失败区分，操作影响、权限及恢复可判断；图表漂亮不能代替可解释数据 |
| 高责任专业/公共服务 | 在较高错误代价或责任要求下正确判断并完成事务 | 表达依据、风险、责任与流程位置，支持阅读、纠错和必要的辅助方式 | 仅依据真实领域输入定义校验、确认和追溯；检查草稿、纠正、进度与失败恢复，不把此分类当成满足医疗/金融/政务等合规要求 |
| 内容/社区/发布 | 阅读、创作、交流，以及控制内容的保存与发布范围 | 区分阅读与编辑，按媒介呈现内容；草稿、预览、发布等只在已定义时出现 | 实际保存状态、可见范围和发布后果；若业务有审核/删除/申诉，检查其结果与恢复，不自动增加这些功能 |
| 游戏/沉浸式体验 | 在连续情境中理解局面、做决策并获得即时反馈 | 信息与当前行动相关，界面让位于必要的内容或场景；适配实际屏幕与输入 | 操作时序、规则可理解性、中断恢复；需要声音/动效/触觉时检查可控性与替代反馈，不套工作台或营销页 |
| AI/对话/Agent（通常为叠加约束） | 表达意图、理解生成或执行结果、控制后续动作 | 先选所属业务的主骨架；聊天只是可能入口，复杂结果可落到对象/工作区 | 区分建议与已执行，说明来源/不确定性、执行范围、真实进度和结果；有外部影响时核对授权和恢复，不用“AI 风格”替代任务设计 |

## 3. 接入阶段和产物

- **C**：选择能支撑场景的入口、空间、对象分组、页面职责与返回关系；分类不自动变成菜单清单。
- **D**：把方向落实到一张代表页与一条链路，验证信息主次、密度、动作和反馈；只承担流程原型所需的方向，不提前宣称最终视觉已确认。
- **E**：在行为确认后，沿用基线约束生成可比较的视觉候选，再展开、精修与复验；已有设计系统按 `15` 决定沿用或获准探索。三套候选保持相同角色、内容、状态与关键行为，改变视觉表达，不拿三种业务方案冒充三种风格。

在现有阶段说明和 `15` 的设计任务包中保留以下摘要，不另建类型报告；下游引用这一条有效记录：

```markdown
- 类型基线及依据：<主骨架；叠加约束；关联用户/SC/UC、使用端与来源版本>
- 必须支持的体验：<最重要的任务、要看清的事实、主要操作及错误代价>
- 结构/交互/感知取舍：<采用哪些原则及理由；不适用项不凑数>
- 既有规范与差异：<复用组件/品牌；冲突及获准调整范围>
- 验证：<代表页面/状态；可观察的 UX/AC 要求；证据或待验证范围>
```

## 4. 检查与迭代

用同包专家的既有能力诊断具体问题：P2-1/P2-2 关注心智与负担，P4-1/P4-4/P4-5 关注空间、入口和返回，P5-3/P5-4 关注反馈与恢复，P6-3/P6-4/P6-5 关注等待、中断与异步，P7-2/P7-6 关注重点与包容。编号和含义以 [能力索引](04-产品判断能力索引.md) 为准；本表不新增编号，也不替代 `04/06/07` 的质量门或 `24` 的文案/交互复核。

视觉辅助 Skill 只在这一任务与基线内提供建议；风格名称、检索结果或截图相似不能作为产品正确的证据。复核真实页面与链路是否满足所选要求，记录版本、覆盖和未验证处；出现新证据时更新同一条基线及受影响材料，不追改旧版确认。没有真实用户或动态操作证据，不宣称分类和设计效果已获验证。
