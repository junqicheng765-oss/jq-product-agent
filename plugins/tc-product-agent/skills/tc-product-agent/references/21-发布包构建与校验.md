# 发布包构建与校验

版本：v0.5｜用途：确保分享给他人的 JQ Product Agent 是纯净、独立、可校验的运行包。

## 1. 开发源与分发物分离

- 开发侧可以保留内部确认、历史版本、试验档案和问题归因。
- 独立使用包只包含通用运行规则、模板、冻结标准、源文档和校验脚本。
- 推荐外发物是同版本 `tc-product-agent` Plugin（展示名 JQ Product Agent），包含主 Skill、A–F 六个阶段 Skill、`jq-demo-quality` 与固定版本的 `ui-ux-pro-max`、`impeccable` 共十项；直接规则包用于审阅、移植或不支持 Plugin 的环境。
- 两项外部 Skill 的源码、脚本/数据与许可证已随包复制，来源与本地适配见 `third_party/README.md`。不要把打包等同于已验证真实产出，不能在安装时自动更新外部 Skill 或下载缺失引擎。
- 可选 Codex Subagent 只是调用 Skill 的执行角色，不是安装 Skill 的替代品，也不是默认必装项。

## 2. 分发物不得包含

- 任何样本项目的名称、需求、PRD、Demo、Figma 节点、组件或实现状态；
- 内部 `history/`、验证工作区、确认编号、回归记录或协作对话；
- 本机绝对路径、个人信息、账户、凭据或内部系统地址；
- 未被包内携带的外部文件依赖；
- 把已准备、已生成、已发送、已接收、已实现或已验收混写的说明。

## 3. 发布前检查

若同时维护独立规则包，在该规则包根目录运行：

```bash
bash scripts/validate-package.sh
```

Plugin 源目录不携带上述规则包脚本，应在开发环境另外运行 Skill 与 Plugin 官方结构校验。校验应至少覆盖：必需文件存在、相对引用可用、manifest 版本和名称合法、Skill 可发现、没有脚手架占位符、没有内部历史和本机路径。

## 4. 独立安装与行为验证

结构校验通过后，在没有来源项目上下文的新 Codex 会话中：

1. 安装 Plugin，确认主 Skill、A–F 六个阶段 Skill、`$jq-demo-quality` 与两项外部视觉 Skill 共十项都可发现；
2. 用 E-A、E-B、E-C 中至少一个冻结样本启动；
3. 确认先识别 H/P/E，P 模式按 A–F 判断门展示、按 S1–S7 内部生产；
4. 确认默认交付合同包含产品基线、可操作产品原型、设计交付物和研发交接包；
5. 确认缺少事实、工具或授权时会限定阻断，不伪造完成；
6. 验证 D/E 才按需调用外部视觉 Skill、模板按项目生成而不复制样本事实；记录首轮观察提示，再运行第二轮无辅助试用。

未完成上述安装与行为验证时，只能标记为“候选发布包”，不能宣称别人已经可以稳定安装和使用。
