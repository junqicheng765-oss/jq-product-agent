# 48 项能力评估标尺

版本：v0.4｜用途：把能力索引变成基于证据的产品质量判断

## 使用规则

对适用项记录一个质量结论：`证据不足`、`基本成立`、`较强` 或 `明显不足`。这些不是可相加的总分；存在关键阻断缺口时，不得因其他项较强而宣称整体可交付。

- **证据不足**：当前不能判断，需说明缺少的事实、设计、原型或实现验证。
- **基本成立**：有明确产品判断和代表场景，但边界或验证仍有限。
- **较强**：判断能处理主要反例、取舍和边界，并有相称的证据或可验证要求。
- **明显不足**：缺少关键定义，和已知事实冲突，或只能靠表面文案/视觉掩盖风险。

## P1 产品逻辑

| ID | 基本成立：至少应有 | 较强：还应能处理 | 明显不足信号 |
| --- | --- | --- | --- |
| P1-1 | 明确用户、场景、问题和可观察结果 | 说明首期取舍、反例和成功验证 | 只有口号、功能清单或业务指标 |
| P1-2 | 领域规则有来源，事实与建议分开 | 处理来源冲突、例外与失真风险 | 用行业习惯替代真实领域事实 |
| P1-3 | 核心对象、身份、职责和边界明确 | 对象可支持新场景而不改名混用 | 把页面、按钮或字段当成对象定义 |
| P1-4 | 归属、引用、数量和权限关系可推导 | 处理多方关联、解除和历史保留 | 关系靠名称/界面位置猜测 |
| P1-5 | 状态含义、触发者和合法转换明确 | 处理并发、回退、终态与跨对象影响 | 把加载、按钮点击或通知当业务状态 |
| P1-6 | 条件、优先级和结果一致可解释 | 处理规则冲突、例外和权限变化 | 同一条件在不同入口得到不同结果 |
| P1-7 | 相关异常和不可接受结果有恢复路径 | 明确错误成本、降级和人工补救 | 用“稍后重试”代替结果未知设计 |
| P1-8 | 历史、版本或新规则变化有兼容边界 | 明确迁移、替代和旧数据解释 | 新功能覆盖旧事实且无追溯 |

## P2 认知与心理引导

| ID | 基本成立：至少应有 | 较强：还应能处理 | 明显不足信号 |
| --- | --- | --- | --- |
| P2-1 | 基于用户已有经验解释核心对象 | 识别不同角色的理解差异和误解风险 | 直接把内部术语要求用户学习 |
| P2-2 | 当前任务只暴露必要信息和选择 | 逐步揭示复杂性且不隐藏关键影响 | 通过删信息让人无法判断 |
| P2-3 | 开始、继续、拒绝或退出都有合理条件 | 动机不靠虚假紧迫或强制路径维持 | 用强制完成/打卡代替真实价值 |
| P2-4 | 范围、结果和限制表达可预测 | 结果未知、权限不足和自动行为可解释 | 把尝试、发送或复制说成成功 |
| P2-5 | 同类对象/动作复用稳定规律 | 新场景能迁移，帮助会逐步退场 | 每页另造一套规则或长期依赖教程 |
| P2-6 | 等待、错误和高压时仍可理解下一步 | 保留控制感、减少焦虑并支持恢复 | 用空泛安慰或倒计时掩盖不确定 |

## P3 语义与表达

| ID | 基本成立：至少应有 | 较强：还应能处理 | 明显不足信号 |
| --- | --- | --- | --- |
| P3-1 | 名称对应真实对象且跨入口一致 | 区分相近概念并支持新角色理解 | 同一词指对象、动作和状态三件事 |
| P3-2 | 动作名说明范围和主要后果 | 高风险/不可逆操作包含影响说明 | “删除/完成/发布”与实际结果不符 |
| P3-3 | 当前、历史、等待、成功、失败可区分 | 跨端/异步后仍不误导状态 | 只用颜色、图标或瞬时提示表达 |
| P3-4 | 复杂规则被转成可判断的信息 | 解释例外、依据和下一步而非堆术语 | 把系统内部错误直接抛给用户 |
| P3-5 | 页面、消息、帮助和不同端术语一致 | 规则变更后所有关键触点同步 | 同一动作多种名称且结果不一致 |
| P3-6 | 语气适合角色、风险和情境 | 准确、直接且不牺牲行动性 | 为“亲切”弱化风险或专业准确性 |

## P4 空间与结构

| ID | 基本成立：至少应有 | 较强：还应能处理 | 明显不足信号 |
| --- | --- | --- | --- |
| P4-1 | 对象有可理解的归属与呈现位置 | 多对象关系增长后仍容易定位 | 按页面开发顺序而非对象组织 |
| P4-2 | 分组层级反映任务和关系 | 支持扫描、比较、变化和例外定位 | 仅为视觉整齐堆叠分类 |
| P4-3 | 关键对象和行动在目标设备可用 | 跨端保持对象身份、上下文和风险信息 | 为截图一致牺牲窄屏/放大可用性 |
| P4-4 | 用户在需要时可发现正确入口 | 高价值低频和异常入口也可找到 | 功能存在但只能靠培训或记忆进入 |
| P4-5 | 当前位置、来源和返回去向清楚 | 深链、筛选、失权后仍安全返回 | 返回丢上下文或将人带到错误对象 |
| P4-6 | 跨页面/角色/端的任务链路明确 | 中断、转交和外部跳转后可续办 | 用跳转链接代替完整任务衔接 |
| P4-7 | 新对象、历史和规模变化有组织策略 | 稳定 ID、版本和结构变化可兼容 | 靠改名称或人工整理维持结构 |

## P5 交互与反馈

| ID | 基本成立：至少应有 | 较强：还应能处理 | 明显不足信号 |
| --- | --- | --- | --- |
| P5-1 | 用户目标与操作之间映射直接 | 同一意图有多入口时仍保持业务一致 | 为系统方便强迫用户绕路操作 |
| P5-2 | 操作、条件、禁用原因和后果可理解 | 新手与高频用户均能发现必要行动 | 操作藏在悬浮、右键或无解释禁用中 |
| P5-3 | 操作后区分已接收、处理中和实际结果 | 有对象内回查与局部失败反馈 | 只弹成功提示，不证明业务结果 |
| P5-4 | 可取消、修正、重试或恢复的范围明确 | 避免重复并保留关键上下文 | 声称可撤销却无法恢复真实影响 |
| P5-5 | 高风险动作核对对象和影响 | 防错与效率按风险分级，不滥用确认 | 对所有动作同样二次确认或无保护 |
| P5-6 | 同对象/动作在不同路径语义一致 | 键盘、移动、消息和页面结果一致 | 多入口各自调用不同规则 |
| P5-7 | 高频操作降低动作和记忆成本 | 效率与错误率、检查和恢复共同验证 | 快捷方式隐藏范围或放大误操作 |

## P6 过程与状态

| ID | 基本成立：至少应有 | 较强：还应能处理 | 明显不足信号 |
| --- | --- | --- | --- |
| P6-1 | 生命周期阶段、责任和可用动作明确 | 终止、归档、恢复和历史关系一致 | 只有“进行中/完成”掩盖真实过程 |
| P6-2 | 变化的时间、主体和原因可理解 | 多方/多次变化可追溯并解释优先级 | 最新展示覆盖了关键历史与原因 |
| P6-3 | 等待说明真实状态、可离开性和下一步 | 不伪造进度，超时后可判断恢复动作 | 无限加载或假百分比 |
| P6-4 | 中断后输入、结果和重复风险有处理 | 刷新/换端/弱网后能安全继续 | 一断网就让用户重做或重复提交 |
| P6-5 | 异步结果和通知回到正确当前对象 | 处理乱序、去重、过期和无通知场景 | 通知是否送达决定业务是否成功 |
| P6-6 | 超时、失败、部分成功和降级如实表达 | 有可执行补救和责任归属 | 把未知说成失败/成功，或沉默丢失 |
| P6-7 | 长任务和跨场景保持身份与上下文 | 权限/版本变化后连续且不误用旧状态 | 只依赖浏览器当前页维持过程 |

## P7 感知体验设计

| ID | 基本成立：至少应有 | 较强：还应能处理 | 明显不足信号 |
| --- | --- | --- | --- |
| P7-1 | 关键事实、风险和行动有明确感知目标 | 不同情境明确优先感知什么 | 只写“简洁、高级、好看” |
| P7-2 | 信息和操作层级符合当前任务 | 历史、风险、异常与主任务不相互遮挡 | 以字号或装饰偏好代替业务优先级 |
| P7-3 | 同类状态、控件和反馈有稳定秩序 | 异常、空态、长内容和跨端也一致 | 只复制正常页，异常页失序 |
| P7-4 | 强度、密度和节奏不制造错误心理预期 | 高压/等待时支持平静和决断 | 用庆祝、倒计时或恐慌色制造假确定性 |
| P7-5 | 额外感官反馈有业务必要性和关闭方式 | 兼顾静音、减少动态和环境限制 | 无目的声音/动画干扰，或仅靠其传达结果 |
| P7-6 | 文本、颜色、键盘、放大和输入要求明确 | 真实设备/辅助技术场景验证 | 只以颜色、悬浮、精细手势传达关键内容 |
| P7-7 | 体验服务理解、效率和长期使用 | 细节、比例、节奏和异常状态都克制可靠 | 以流行风格、装饰或空白证明品质 |

## 结论格式

评审输出至少写：能力 ID、质量结论、产品条目/场景证据、证据类型（推演/原型/实现）、缺口、影响与下一步。涉及高风险、权限、状态、外部影响或不可恢复损失的问题，即使其他项较强，也列为阻断或重大问题。
