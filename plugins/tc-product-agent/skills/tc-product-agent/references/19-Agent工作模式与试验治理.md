# Agent 工作模式与试验治理

版本：v0.4｜用途：把“造锤子”“造房子”和“观察造房子”硬隔离，防止验证过程变成项目实施。

## 1. 三种模式

| 模式 | 目的 | 允许输入 | 允许产出 | 默认停止点 |
| --- | --- | --- | --- | --- |
| H 能力包迭代 | 定义、改进和发布 TC Product Agent | Agent 产品定义、通用标准、跨样本发现、版本决定 | 通用规则、模板、版本候选、发布校验 | 候选版本和回归要求；不继续任何样本项目 |
| P 项目运行 | 帮助调用者完成其项目的产品工作 | 当前项目事实、需求、资料、确认和授权 | 当前项目的产品基线、产品原型、设计交付物、研发交接包 | 用户约定的项目阶段或默认完整交付；不修改 Agent 通用规则 |
| E 受控试验 | 验证一个冻结版本是否有效 | 冻结 Agent、冻结样本、试验协议和允许暴露的事实 | 运行产物、观察记录、评分、归因和回归结论 | 协议预定终点；不自动进入真实设计、研发或发布 |

普通使用者带着自己的需求调用时默认进入 P。只有用户明确要求修改 TC Product Agent 本身时进入 H；只有明确给出被测版本、样本和验证目的时进入 E。不能因为项目中发现了问题，就在 P 模式顺手修改能力包；也不能为证明能力而在 E 模式继续交付样本项目。

## 2. 每轮开始必须声明

每轮实质工作开头用自然语言标明：

```text
当前：{TC Product Agent 能力包迭代 / 项目产品工作 / 受控试验}｜{真实状态}｜范围：{本轮允许处理的内容}
```

工作区内部同时记录：模式、使用的 Agent 版本、允许读取的输入、允许写入的目录、停止点和禁止动作。用户表面不要求理解 H/P/E 术语，但必须能知道当前是在改 Agent、做自己的项目，还是做验证。

## 3. 写入边界

| 当前模式 | 可以写入 | 禁止写入 |
| --- | --- | --- |
| H | Agent 开发源、通用规则、发布候选、内部版本记录 | 样本项目的 PRD、Demo、Figma、研发交付 |
| P | 调用者当前项目的 `product/`、原型和经授权交付文件 | Agent 分发包、冻结标准、其他项目或验证档案 |
| E | 隔离验证工作区中的运行产物、观察、评分与归因 | 真实项目当前基线、正式 Agent 包、外部设计或研发目标 |

一个项目问题只有在 E 模式完成归因，并满足升级门槛后，才可以在新的 H 模式中成为候选改进。不得直接复制项目名称、对象、规则、组件、节点或历史决定到通用包。

## 4. 模式切换合同

切换前必须向人说明并记录：

1. 为什么需要切换；
2. 从哪个模式切到哪个模式；
3. 新模式使用什么版本和输入；
4. 允许新增或修改哪些成果；
5. 新的停止点、禁止动作和需要的授权。

没有明确切换时保持原模式。用户说“继续”只表示在当前已展示范围内继续，不自动改变模式或授权边界。

## 5. E 模式试验冻结

试验开始前冻结：被测版本、样本输入、参与者角色、任务终点、禁止动作、预期证据和评分规则。动态项目目录不能直接作为完整样本；应复制或列明只读快照，避免试验过程中被其他工作污染。

首轮可采用观察式试用：观察者可以解释工具或交互方式，但不得补业务事实、替使用者作产品决定或静默改成果。每次介入记录触发原因、提示内容和影响。第二轮使用同类任务进行无辅助验证；观察者只记录，除非触发预先定义的安全或阻断救援条件。

## 6. 停止与恢复

- H：形成候选版本和回归要求后停止；没有用户确认，不把候选发布成正式版本。
- P：到达约定交付终点后说明三类默认成果的真实状态；外发或下游实施需要另行授权。
- E：到达协议终点立即停止项目动作，只输出评分和归因；真实项目需要继续时另开 P 模式。
- 发生模式不明、写入目标不明或输入边界冲突时，完成不依赖它们的分析并停止相关写入，向用户展示具体恢复条件。
