# 设计交付与 Figma 回传规范

版本：v0.13｜用途：从已确认的产品行为走到可回审的视觉设计和有样式可操作 Demo；不把视觉稿变成业务规则来源。对齐决议见仓库 `docs/设计交接-决议冻结.md`（R1–R7）。

## 1. 适用与边界

产品原型属于默认产品交付，至少要能操作并验证核心流程、规则、关键状态和返回路径。D 阶段的流程原型可以是低/中保真，但低/中保真只允许灰框加文字，用来验证入口和步骤；一旦上颜色、字体、图标或图片，必须先走 `$design-thinking-os` 并写完 `design-decisions.md`。默认终点还包含面向研发的有样式、可操作 Demo：产品基线 → 流程原型与模块行为确认 → **设计流程（决定文件）** → 视觉方案选择 → 全范围设计与精修 → 设计还原 Demo → 产品回审 → 研发交接。它是设计与行为输入，不是生产代码或部署验收。

**人设计师是视觉主责。** Agent 仅在明确授权的文件/Frame/动作范围内代写或精修，且每次回传须提供可被人核验的节点与画面证据；不得以 Agent 自称完成代替人审。

**已有本产品 Figma 设计稿时，正式视觉与有样式交付以 Figma 为设计主稿**：在 Figma 完成本次范围后，再用对应 Frame 的定位链接（需要代码还原时再用 Dev Mode/MCP 设计上下文）还原 Demo；宿主编码 Agent 承担还原，不另起设计主稿。**D 允许先用灰框加文字的可操作流程骨架验证链路**（须标注非最终视觉）；一旦上颜色、字体、图标或图片，必须先有 `design-decisions.md`。升入正式视觉或宣称有样式交付前，须回到 Figma 完成本次范围，禁止用本地 HTML/临时代码冒充 Figma 设计完成。E 按范围扩展和精修 Figma 后更新 Demo，不要求先画完整系统才能验证代表链路。文字规则、流程推演可以先做。明确只作外部灵感参考的链接不属于本产品主稿。

若环境没有原型或 Figma 写入工具、账户、执行者或权限，仍生成同规格任务包并明确“原型/设计待制作”；用户明确选择或委托采用本地视觉路线（可在 Codex、Cursor 等宿主执行）时，可在已授权的本地范围自行生成视觉与 Demo，不因缺项静默切换，也不把本地产物称为 Figma 稿。**人设计师仅凭短清单接包制作时，不因 Agent 工具链未配齐而阻断**；Agent 代写或自动还原所需的工具缺项仍须如实标出。不得用文字规格或任务包冒充已经可操作的原型，也不得伪称已经写入、已生成或已验收。

实际写入（人或 Agent）只在用户授权、目标文件/页面/写入范围明确时进行。写入前必须完成 [Figma 执行前核对卡](18-Figma执行前核对卡.md)，确认目标、页面或 Frame、执行者和工具、写入授权、受保护对象、视觉基线与回传证据责任。设计执行者可探索布局和视觉表现，但不得静默改变目标、对象、权限、状态、规则、范围或验收。

## 2. 启动分流与执行顺序

**界面执行硬门：** 创建任何 HTML、Figma 节点、图片或给用户看的页面之前，必须完整读取并执行同包 [design-thinking-os](../../design-thinking-os/SKILL.md)，并在任务目录写完四块 `design-decisions.md`。本规范、C/D/E 阶段 Skill 和主 Agent 里的 U0/V0/IconScout 摘要不能代替执行。没有决定文件，不得出图。

设计师侧的语境翻译、方法调用、UI 三路分流、风格参数字典绑定、IconScout 资产调取、真实摄影库 `IM`、生图与动效分流及交付前 `QA0` 三维验收由 `$design-thinking-os` 承担；实际 Figma 配置引导、生成/精修、结果回传及 Dev Mode 到 Demo 的执行由同包 [jq-figma-workflow](../../jq-figma-workflow/SKILL.md) 承担，且必须带上已写完的决定文件。主产品 Agent 继续负责事实、专业要求、关键决定和交付判断。安装本 Skill 不安装 Figma 服务或取得账号权限。

本节仅用于当前任务包含设计/Demo 交付的情况；资料维护、解释或局部文案咨询不自动探测设计工具。按 [产品类型设计基线](25-产品类型设计基线.md) 复用 C/D 的主骨架与叠加约束，作为视觉任务和复核的输入；类型本身不决定工具路线或增加写入授权。

首次设计按 [设计能力初始化与复用](26-设计能力初始化与复用.md) 询问是否使用 Figma，引导 Agent、MCP、Computer Use 和账号权限配置，并绑定用户指定文件；不自行创建 Figma 项目或文件。实际页面/原型制作前须有明确路线依据并展示设计准备结果；未回答选项、业务确认均不代替路线选择。配置在本任务内持久复用，已有链接区分现状参考与编辑目标，后续只核对变化，不每轮重装或索取链接。登录或 `whoami` 不证明目标可读可写，按实测细化下列路线。存量系统继续制作/修改原型前须满足 `26` 第 5 节的现状界面参考条件；缺失时继续业务分析，暂停受影响页面制作。初始化不替代风格选择或 `18` 的实际写入核对。

| 路线 | 条件 | 处理 |
| --- | --- | --- |
| Figma 完整路线 | 目标访问、编辑权限及本次需要的工具已验证；需要生成时才要求 Figma Agent，需精修时核对宿主 GUI 操作能力，需要代码还原时核对 Figma MCP；写入范围已获授权 | 先按 2.2 逐页选择直接编辑或生成后精修。仅当新产品且无设计系统/品牌基线且需要选择视觉气质时，比较三套代表页；已有设计系统或品牌则默认沿用，不因新增页面自动重选风格。回审后按需通过 MCP 设计上下文、截图和素材还原有样式 Demo。 |
| Figma 部分路线 | 本次确实需要的生成、编辑或还原能力缺失 | 执行已验证且已授权的部分，明确缺口及回传方式；缺少本次不需要的 Figma Agent 不构成阻断，也不使直接编辑路线自动变成未完成。人设计师可继续在已授权目标内制作并回传。 |
| 本地视觉路线 | 无本产品 Figma 主稿且已有明确本地制作选择/委托；已有主稿时须有明确改走本地设计的例外决定，不能以工具缺项、笼统委托或业务确认替代 | 依据同一产品与视觉任务包，按下述风格选择要求展示代表页候选或核对既有基线；选择依据成立后再扩展正式视觉并验证可操作、有样式 Demo。Figma 链接/稿状态为未产出，不伪造设计还原证据。若交付约定要求 Figma，保留为待补，不宣称该项完成。宿主示例包括 Codex、Cursor，合同不绑定单一宿主。 |

**三套风格候选**仅在「新产品且无设计系统/品牌基线且需要选择视觉气质」时强制；已有设计系统或品牌规范时默认沿用并记录依据。若探索意味着改品牌或重设计，先取得单独授权。选定方向只确认视觉取舍，不替代流程和规则确认。任何路线均在已确认的行为范围上工作，新增业务冲突回产品事实源处理。

### 2.1 风格选择与进度说明（所有设计路线共用）

- **先说明时点**：D 首次展示代表页面时，说明当前视觉是流程验证用的临时方向、已确认方向还是沿用基线，及风格选择将在什么条件后进行；E 先扩展行为时，在阶段交付回复中说明视觉选择尚未完成、触发条件及下一产物。说明放在对话和交付说明，不往用户使用的界面加入 Demo 解说。
- **新方向可见再选**：触发三套候选时，必须有真实可打开的同页面图稿或预览；风格名称、配色描述和提示词不能替代候选画面。记录选中版本、适用范围及用户选择的来源，然后才按该方向批量展开正式视觉。D 的灰框流程骨架可提前推进；带样式的代表页必须先有 `design-decisions.md`，且不得自动当作最终视觉选择或有样式交付。
- **沿用要有依据**：已有设计系统或品牌时默认沿用，不强制三套改版；在任务包中引用有效设计系统或页面的版本、可读证据、适用范围及沿用依据。只读到部分文字、尚未取得关键组件/素材时，明确缺口，不能把自行补出的风格称为原系统已还原或最终视觉已确认。
- **尊重明确委托**：用户明确委托 AI 决定视觉方向时，可由 AI 选择并记录委托原意、范围、选中代表页及理由，不再要求相同范围重复选定；“无偏好”“先建议”或未明确审阅范围的“继续”，本身不构成最终视觉选择的委托或确认。已有仍适用的确认不重复索取。
- **同等交付条件**：Figma 和本地视觉路线都保留风格选择/沿用/委托的依据。缺少依据时保持流程候选或设计草案状态，可以继续不依赖它的工作，不能标对应范围的最终设计或有样式交付就绪；交接前按第 7 节核对。咨询、非视觉局部修改不因此启动完整选风格流程，小需求可合并已有审阅窗口。
- **UI 落地三路前置分流与 26+6 风格参数字典（调用 `$design-thinking-os` `U0 / V0`）**：
  进入 UI 与视觉设计时，先按 [methods-ui.md](../../design-thinking-os/methods-ui.md) `U0` 与 [methods-visual.md](../../design-thinking-os/methods-visual.md) `V0` 执行两问三路分流：
  1. **有现成相关页或既有设计规范 → 路线 1 存量延展模式**：直接提取现有页面的 5 个视觉常量（主辅色、背景与卡片层级、圆角、字号阶梯、图标风格），复用既有组件拼装，跳过风格三选一。
  2. **0→1 纯 B 端 / 企业中后台 → 路线 2 公开组件库快搭模式**：直接连接成熟公开组件库（国内：`Ant Design` / `Arco Design` / `TDesign`；国际化：`shadcn/ui` / `MUI` / `Fluent UI`），仅确认「选用库 + 主色 + Default/Compact 密度」3 项即刻搭建。
  3. **0→1 C 端 / 游戏 UI / 强品牌产品 → 路线 3 风格库与 6 维视觉决策漏斗**：先按市场生态与行业严肃度剪枝，从内置 **26+6 风格参数字典**（国际化 `INT-01..08`、国内 `CN-01..08`、游戏与泛娱乐 `GAME-01..10`、通用质感 `TEX-01..06`）中由 Agent 直接选定风格并自动配齐 6 个具体维度（语境明确时零提问；仅方向高度开放时用大白话问 1 个大方向问题，不问细项、不出现风格编号或“六维”等内部术语；①主色与纯色/渐变及辅助色、②底色明暗与带 1%–3% 冷暖倾向的中性灰、③容器与表面材质、④圆角/切角阶梯、⑤字体与等宽数字如 `DIN` 及密度、⑥图标与配图边界）；查表加载精确 Hex、圆角、阴影/毛玻璃、字阶与专用 Prompt 片段写入任务包，先出 1 个核心代表页，自检通过后直接模块化铺开，不停下来等批准。
- **IconScout 双通道资产、双路径生图与三条动效实现链路（调用 `$design-thinking-os` `V5 / V7 / TR5`）**：
  - **人物头像 / 图标 / 3D / 插画 / Lottie**：第一优先级通过 IconScout 双通道（优先调用官方 MCP `https://mcp.iconscout.com/mcp`，未安装时自动回退调用内置 `design-thinking-os/scripts/iconscout.py`，已预置 `Client-ID: 232598791050530`）拉取成套透明底素材，严禁手画劣质 SVG 人脸或图标。
  - **图片与海报生成（`V7` / `IM`）**：真实场景、地点、生活、自然摄影先走 Real Image Library（`IM`：Unsplash / Pixabay / Openverse / Pexels / Wikimedia）；图库无匹配或必须虚构时，才由 Agent 在 Figma 目标图层原位生图。独立海报/运营图/主视觉 KV 先判图文占比并画出 **版面结构草图（`layout_sketch.png`）**，优先采用「版式底板 + 清晰矢量排版字 + 真图或 IconScout 透明底素材快拼（方式 1）」，确需全画幅写实融合光影时才走「结构草图 + 搜直观风格参考垫图（`style_ref.png`）+ 提示词」双垫生图（方式 2），并在支持动图的场景主动询问用户是否升级生成动态版本及说明真实效果预期。这些步骤在 `$design-thinking-os` 内执行，不在本规范复述后直接做。
  - **动效三条实现链路（`TR5`）**：Figma 连线仅作 `FIGMA_MOTION_PREVIEW` 预览；正式 UI 交互动效一律写代码实现（`TR5-A`：CSS/JS/GSAP/客户端代码）；轻量矢量图标/真 `Lottie (.json)`/动态 `SVG` 走矢量源 + IconScout Lottie + 代码生成（`TR5-C`）；代码写不出的复杂 3D/光影/流体动态图与宣传视频走「确认首尾帧静帧垫图 → 调生视频模型 → 转码 `MP4 / WebM / GIF / 动态 WebP`」（`TR5-B`，严禁将视频序列帧位图塞进 Lottie 冒充矢量动画）。

### 2.2 存量设计按页面选择执行方式

先核对有效现状稿，区分已有可编辑页面、需要新增/补齐的整页、仅有截图或不可编辑的参考，在现有设计任务包中记录页面/Frame、改动、执行方式及理由。同一需求可混用下列方式，不要求所有页面使用同一工具。

| 页面情况 | 默认方式 | 执行要求 |
| --- | --- | --- |
| 已有可编辑 Figma 页面上的文案、控件、布局或状态迭代 | Computer Use 直接编辑图层/组件 | 复用原组件、变量和资产，保护已确认内容；不先让 Figma Agent 重画整页 |
| 新增全新页面或缺失整页 | Figma Agent 生成，再由 Computer Use 精修 | 输入已确认流程、页面职责及原系统组件/风格；仅生成授权的新页/Frame，不覆盖相邻既有页；确认实际结果后再直接精修 |
| 同时有旧页改动和新页 | 逐页混合执行 | 旧页直接编辑，新页生成后精修；涉及同一范围的生成与直接编辑串行，使用前一步实际结果 |
| 只有截图、只读稿或不可编辑内容 | 先明确制作目标与可用路线 | 截图可支持延续风格，但不能称其为可直接编辑的图层；不擅自改原文件权限或重建整个项目，按 `26` 绑定目标及 `18` 核对写入范围 |

已有页面即使改动较大，也先评估组件复用及直接编辑；若确需整体重设计，说明理由并依有效授权处理，不把局部需求扩大为改版。新增页面不等于新增品牌风格，有有效基线时不强制三套候选。直接编辑不依赖 Figma Agent 开通；生成新页缺少 Agent 时，只暂停相应生成，不阻断可独立完成的旧页精修。

生成与精修都须查看实际画面/导出，核对修改页、关键状态、相邻内容及共享组件影响；分别记录直接修改和 Agent 生成范围。无法定位或可靠编辑目标图层时先说明缺口，不以反复自然语言重生成冒充局部修改。

**回传与人审**最低需要：准确节点（或文件+页面+Frame）链接、关键页截图/导出、覆盖与缺口、验收结论。需要代码还原时，再取得 Dev Mode/等价定位，通过 Figma MCP 读取同一版本的设计上下文、截图和素材；普通文件链接已能定位准确节点时，由执行方在现有授权内解析/定位，不重复要求用户复制同一链接。节点不明或当前工具/权限无法获取所需信息时，用宿主原生提问工具请求具体 Frame/开发者链接或引导补齐能力，不能只看旧截图就称已完成还原。

核对设计稿版本、页面/状态覆盖及有效审阅或明确委托依据后，才由编码 Agent 还原对应范围的 Demo；引用实际组件、变量和资产，逐页比对布局、内容、样式和状态，并实际走通核心交互。设计缺失的新增页面、支付/异常等状态先回到 Figma 补齐或保留为未覆盖，不由本地代码静默补画后称按稿还原。Figma 与 Demo 持续引用同一有效版本，后续设计变更同步回验。

开发者模式链接是还原定位输入，不保证原封不动还原，也不自动生成代码。分别记录“设计链接可读”“本次设计已形成并有审阅依据”“代码还原已验证”的证据与未覆盖范围，三者不可合并成一句完成；只读旧稿或仅完成本地 HTML 不满足本次 Figma 设计交付。

## 3. 产品原型最低合同

产品原型至少记录：入口与版本、覆盖的 SC/UC、核心页面或界面状态、关键数据与真实文案样例、主要操作、分支/失败/返回路径、未覆盖范围、验证类型和当前结论。静态截图只能作为辅助证据，不能单独满足“可操作”。

产品原型可以先于最终视觉设计，用于验证产品逻辑；D 的灰框加文字可操作骨架满足流程验证即可。带颜色、字体、图标或图片的界面必须先有 `design-decisions.md`。已有 Figma 主稿时，**正式视觉与有样式交付**须在 Figma 形成当前范围后再还原；不能把本地流程原型或 HTML 称为 Figma 设计完成。视觉设计不得删除未覆盖的动态状态或静默改写产品规则。

## 4. 设计任务包

路径：`product/handoff/design/DESIGN-<模块>-任务包.md`。

交给**人设计师**时，正文使用短清单（见下「页面短清单」）；完整进入条件、全状态枚举等放入 §5 页面交互规格或 PRD，不强制塞进任务包首页。交给 **Agent 执行**时，可在同文件保留长字段或由短清单生成执行提示词。

## 5. 页面交互规格

关键页面或状态复杂的模块创建 `DESIGN-<模块>-页面交互规格.md`。每个页面至少定义：页面目标与进入条件、固定布局和内容、字段/控件及校验、默认/加载/空/禁用/无权/失败/部分完成/结果未知状态、操作反馈、跳转/返回、响应式/无障碍、页面级验收。它解释“产品行为如何在页面中表达”，承接短清单未展开的字段，不替代任务包的范围和版本控制。简单页可合并进任务包短清单，不强制另建本文件。

## 6. 回传与产品回审

设计方/Figma 回传后创建 `DESIGN-<模块>-回传与评审.md`，**最低记录**：任务包版本、实际 Figma 文件/页面/节点（或等价定位）、关键页截图或导出、已覆盖与未覆盖、实际差异（无则写无差异）、验收项逐条结论、返工项（若有）、验证边界和下一责任方。发生风格三选一时记录候选及选择依据；发生精修时记录精修范围（未使用则一句说明）；已做 Demo 还原时记录入口和版本。本地视觉路线记录相应本地视觉与 Demo 证据，Figma 字段保持未产出。

**单模块**可将覆盖表嵌在回传文档内，不强制另建矩阵文件。**多模块**再创建 `DESIGN-覆盖矩阵.md`：`SC/UC → 页面/状态 → 任务包版本 → Figma 证据 → 验收结论 → 缺口`。Figma 显示完成、提示词已发送或画面看起来合理都不能代替回审通过。

## 7. 设计就绪与回审门

- 产品原型就绪：存在真实可打开和操作的入口，覆盖与限制可定位；没有最终视觉稿不影响流程原型成立，但没有可操作证据时不得称默认产品交付完成。流程原型就绪 ≠ 有样式交付就绪。
- 设计可开工 / 设计就绪（D1）：
  - **人设计师接包**：短清单 + Figma 目标 + 禁止项齐全即可开工；不因 Agent 的 MCP/GUI 操作等工具链未配齐而阻断。
  - **Agent 或任何人实际写入 Figma 前**：执行前核对卡中的目标、保护范围、授权和回传责任必须明确；否则维持“任务包已准备、未执行”。
  - 当前范围的产品基线、流程与页面职责、关键场景、体验要求、可观察验收应可定位；首次在 Figma 制作代表页不以已有编码 Demo 为前提。
- 回审通过：最低回传证据齐全；已执行 [design-thinking-os QA0 三大维度综合验收](../../design-thinking-os/methods-close.md)（一、用户可用性审查 × 二、审美与视觉品位审查 × 三、设计标准与工程规范审查），任一维度不达标已按病因精准退回对应流程节点完成回炉修改；高风险场景和状态有可定位证据；差异已修正或明确暂缓；设计验证与实现验证边界已说明。
- 有样式交付就绪：所有路线先满足 2.1 的风格选择或沿用依据；Figma 路线分别具备「设计链接可读」「设计稿已确认」；若本任务包含代码还原，另须「代码还原已验证」同版本证据。本地视觉路线记录本地视觉产物、视觉选择依据与 Demo 验证，不要求 Figma 链接，但不能以代码生成或自检代替视觉选择，且需明示没有 Figma 稿。最终 Demo 的文案与关键交互仍按 `24` 专项复核，静态像素接近不等于交互正确。
- 已有 Figma 主稿的附加核对：正式视觉与有样式交付范围内的变更已在 Figma 中形成，有准确 Frame 定位及（还原时）同版本设计上下文和 Demo 对照证据；缺项时不能以“参考过原稿”“本地 Demo 可操作”替代设计完成。明确改走本地设计时保留例外决定及交付差异，不追认此前业务确认。
- 发现业务冲突：回写 `01`/`04` 并标记受影响设计为待复核，不在 Figma 备注中形成新规则。
