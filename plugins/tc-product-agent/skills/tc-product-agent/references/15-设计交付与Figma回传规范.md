# 设计交付与 Figma 回传规范

版本：v0.4｜用途：形成默认产品原型与可执行、可验收的设计工作包；不把视觉稿变成业务规则来源。

## 1. 适用与边界

产品原型属于默认产品交付，至少要能操作并验证核心流程、规则、关键状态和返回路径。它可以是低/中保真交互原型，不等同于最终视觉稿。进入高保真 Demo、Figma 设计或关键页面细化时，设计路径是：产品基线 → 产品原型 → 设计任务包 → Figma/设计方回传 → 产品回审 → 研发交接。

若环境没有原型或 Figma 写入工具、账户、执行者或权限，仍生成同规格任务包并明确“原型/设计待制作”；不得用文字规格或任务包冒充已经可操作的原型，也不得伪称已经写入、已生成或已验收。

实际写入只在用户授权、目标文件/页面/写入范围明确且所需工具可用时进行。写入前必须完成 [Figma 执行前核对卡](18-Figma执行前核对卡.md)，确认目标、页面或 Frame、执行者和工具、写入授权、受保护对象、视觉基线与回传证据责任。设计执行者可探索布局和视觉表现，但不得静默改变目标、对象、权限、状态、规则、范围或验收。

## 2. 产品原型最低合同

产品原型至少记录：入口与版本、覆盖的 SC/UC、核心页面或界面状态、关键数据与真实文案样例、主要操作、分支/失败/返回路径、未覆盖范围、验证类型和当前结论。静态截图只能作为辅助证据，不能单独满足“可操作”。

产品原型可以先于最终视觉设计，用于验证产品逻辑；视觉设计不得删除未覆盖的动态状态或静默改写产品规则。

## 3. 设计任务包

路径：`product/handoff/design/DESIGN-<模块>-任务包.md`。

```markdown
# DesignTaskPackage：<模块>

- taskPackageId / packageVersion：<唯一标识>。
- 产品输入：`01` 版本；SC/UC、R、UX、AC 的引用。
- 本次意图与范围：<要解决什么；允许改什么；不覆盖什么>。
- Figma 目标：<文件、页面、选区、允许写入范围>。
- 受保护对象：<不得覆盖、移动、删除或改写的对象>。
- 视觉/组件基线：<品牌、设计系统、内容密度、无障碍约束；未知项明确待定>。

## 必须生成的页面或 Frame
### <页面 ID> <页面名>｜<状态/分支>
- 进入条件与来源：<入口、权限、前置状态>。
- 用户任务与信息：<用户要判断或完成什么>。
- 必须展示：<对象、字段、状态、文案、风险或依据>。
- 动作与结果：<操作、反馈、状态变化、返回去向>。
- 异常/恢复：<空、加载、无权、失败、部分完成、未知结果等>。
- 关联：SC/UC、R、UX、AC。

## 禁止项
<不得把等待画成失败；不得只靠颜色表达状态；不得展示越权内容等>。

## 验收
| 验收项 | 可观察证据 | 关联条目 |
| --- | --- | --- |
| <要求> | <Figma 节点、截图或导出> | SC/R/AC |

## 执行提示词
<由上述事实生成；提示词是传输载体，不高于产品基线>。
```

系统级或多模块任务要求每个模块只有一个有效交互总画板。返工必须回到该画板；当前有效、待确认和旧版参考可区分；临时画板和旧提示词不应混入交付内容。

## 4. 页面交互规格

关键页面或状态复杂的模块创建 `DESIGN-<模块>-页面交互规格.md`。每个页面至少定义：页面目标与进入条件、固定布局和内容、字段/控件及校验、默认/加载/空/禁用/无权/失败/部分完成/结果未知状态、操作反馈、跳转/返回、响应式/无障碍、页面级验收。它解释“产品行为如何在页面中表达”，不替代任务包的范围和版本控制。

## 5. 回传与产品回审

设计方/Figma 回传后创建 `DESIGN-<模块>-回传与评审.md`，记录：任务包版本、实际 Figma 文件/页面/节点、截图或导出、已覆盖与未覆盖页面/状态、实际差异、验收项逐条结论、返工项、验证边界和下一责任方。

多模块 Demo 再创建 `DESIGN-覆盖矩阵.md`：`SC/UC → 页面/状态 → 任务包版本 → Figma 证据 → 验收结论 → 缺口`。Figma 显示完成、提示词已发送或画面看起来合理都不能代替回审通过。

## 6. 设计就绪与回审门

- 产品原型就绪：存在真实可打开和操作的入口，覆盖与限制可定位；没有最终视觉稿不影响流程原型成立，但没有可操作证据时不得称默认产品交付完成。
- 设计就绪（D1）：产品基线、产品原型、关键场景、体验要求、可观察验收和写入范围已明确；若需实际 Figma 写入，执行前核对卡中的目标、保护范围、授权和回传责任也必须明确；否则返回对应产品阶段或维持“任务包已准备、未执行”。
- 回审通过：高风险场景和状态有可定位证据；差异已修正或明确暂缓；设计验证与实现验证边界已说明。
- 发现业务冲突：回写 `01`/`04` 并标记受影响设计为待复核，不在 Figma 备注中形成新规则。
