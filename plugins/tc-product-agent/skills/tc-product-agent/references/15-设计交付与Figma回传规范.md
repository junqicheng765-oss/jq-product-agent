# 设计交付与 Figma 回传规范

版本：v0.12｜用途：从已确认的产品行为走到可回审的视觉设计和有样式可操作 Demo；不把视觉稿变成业务规则来源。

## 1. 适用与边界

产品原型属于默认产品交付，至少要能操作并验证核心流程、规则、关键状态和返回路径。D 阶段的流程原型可以是低/中保真，不等同于最终视觉稿。默认终点还包含面向研发的有样式、可操作 Demo：产品基线 → 流程原型与模块行为确认 → 视觉方案选择 → 全范围设计与精修 → 设计还原 Demo → 产品回审 → 研发交接。它是设计与行为输入，不是生产代码或部署验收。

**已有本产品 Figma 设计稿时，本次设计先在 Figma 完成，再用对应 Frame 的 Dev Mode 链接及设计上下文还原 Demo；Codex 承担设计还原，不另起设计主稿。** D 先完成代表链路所需的 Figma 页面/状态再还原，E 按范围扩展和精修 Figma 后更新 Demo，不要求先画完整系统才能验证代表链路。临时视觉、低保真或赶进度均不能豁免；文字规则、流程推演可以先做。明确只作外部灵感参考的链接不属于本产品主稿。

若环境没有原型或 Figma 写入工具、账户、执行者或权限，仍生成同规格任务包并明确“原型/设计待制作”；用户明确选择或委托采用 Codex 时，可在已授权的本地范围自行生成视觉与 Demo，不因缺项静默切换，也不把 Codex 产物称为 Figma 稿。不得用文字规格或任务包冒充已经可操作的原型，也不得伪称已经写入、已生成或已验收。

实际写入只在用户授权、目标文件/页面/写入范围明确且所需工具可用时进行。写入前必须完成 [Figma 执行前核对卡](18-Figma执行前核对卡.md)，确认目标、页面或 Frame、执行者和工具、写入授权、受保护对象、视觉基线与回传证据责任。设计执行者可探索布局和视觉表现，但不得静默改变目标、对象、权限、状态、规则、范围或验收。

## 2. 启动分流与执行顺序

实际配置引导、Figma 生成/精修、结果回传及 Dev Mode 到 Demo 的执行由同包 [jq-figma-workflow](../../jq-figma-workflow/SKILL.md) 承担，按需读取其操作与还原手册；主产品 Agent 继续负责事实、专业要求、关键决定和交付判断。安装本 Skill 不安装 Figma 服务或取得账号权限。

本节仅用于当前任务包含设计/Demo 交付的情况；资料维护、解释或局部文案咨询不自动探测设计工具。按 [产品类型设计基线](25-产品类型设计基线.md) 复用 C/D 的主骨架与叠加约束，作为视觉任务和复核的输入；类型本身不决定工具路线或增加写入授权。

首次设计按 [设计能力初始化与复用](26-设计能力初始化与复用.md) 询问是否使用 Figma，引导 Agent、MCP、Computer Use 和账号权限配置，并绑定用户指定文件；不自行创建 Figma 项目或文件。实际页面/原型制作前须有明确路线依据并展示设计准备结果；未回答选项、业务确认均不代替路线选择。配置在本任务内持久复用，已有链接区分现状参考与编辑目标，后续只核对变化，不每轮重装或索取链接。登录或 `whoami` 不证明目标可读可写，按实测细化下列路线。存量系统继续制作/修改原型前须满足 `26` 第 5 节的现状界面参考条件；缺失时继续业务分析，暂停受影响页面制作。初始化不替代风格选择或 `18` 的实际写入核对。

| 路线 | 条件 | 处理 |
| --- | --- | --- |
| Figma 完整路线 | 目标访问、编辑权限及本次需要的工具已验证；需要生成时才要求 Figma Agent，需精修时核对 Computer Use，还原时核对 MCP；写入范围已获授权 | 先按 2.2 逐页选择直接编辑或生成后精修。新建且无视觉基线时比较三套代表页；存量沿用有效设计，不因新增页面自动重选风格。回审后通过 MCP 设计上下文、截图和素材还原有样式 Demo。 |
| Figma 部分路线 | 本次确实需要的生成、编辑或还原能力缺失 | 执行已验证且已授权的部分，明确缺口及回传方式；缺少本次不需要的 Figma Agent 不构成阻断，也不使直接编辑路线自动变成未完成。 |
| Codex 路线 | 无本产品 Figma 主稿且已有明确本地制作选择/委托；已有主稿时须有明确改走本地设计的例外决定，不能以工具缺项、笼统委托或业务确认替代 | 依据同一产品与视觉任务包，按下述风格选择要求展示代表页候选或核对既有基线；选择依据成立后再扩展正式视觉并验证可操作、有样式 Demo。Figma 链接/稿状态为未产出，不伪造设计还原证据。若交付约定要求 Figma，保留为待补，不宣称该项完成。 |

新产品且无既定视觉基线时，三套候选用同一代表页面、同一内容和状态，分别说明风格理由、品牌匹配和主要风险，避免同时改变业务内容造成无法比较。已有设计系统的迭代先复用其组件与规范；若三套方向意味着改品牌或重设计，先请人决定是否允许探索。选定方向只确认视觉取舍，不替代流程和规则确认。任何路线均在已确认的行为范围上工作，新增业务冲突回产品事实源处理。

### 2.1 风格选择与进度说明（所有设计路线共用）

- **先说明时点**：D 首次展示代表页面时，说明当前视觉是流程验证用的临时方向、已确认方向还是沿用基线，及风格选择将在什么条件后进行；E 先扩展行为时，在阶段交付回复中说明视觉选择尚未完成、触发条件及下一产物。说明放在对话和交付说明，不往用户使用的界面加入 Demo 解说。
- **新方向可见再选**：无既定视觉基线时，三套候选必须有真实可打开的同页面图稿或预览；风格名称、配色描述和提示词不能替代候选画面。记录选中版本、适用范围及用户选择的来源，然后才按该方向批量展开正式视觉。D/E 的临时流程原型可提前推进，但不得将其样式自动当作最终选择。
- **沿用要有依据**：迭代需求不强制三套改版；在既有任务包中引用有效设计系统或页面的版本、可读证据、适用范围及沿用依据。只读到部分文字、尚未取得关键组件/素材时，明确缺口，不能把自行补出的风格称为原系统已还原或最终视觉已确认。
- **尊重明确委托**：用户明确委托 AI 决定视觉方向时，可由 AI 选择并记录委托原意、范围、选中代表页及理由，不再要求相同范围重复选定；“无偏好”“先建议”或未明确审阅范围的“继续”，本身不构成最终视觉选择的委托或确认。已有仍适用的确认不重复索取。
- **同等交付条件**：Figma 和 Codex 路线都保留风格选择/沿用/委托的依据。缺少依据时保持流程候选或设计草案状态，可以继续不依赖它的工作，不能标对应范围的最终设计或有样式交付就绪；交接前按第 7 节核对。咨询、非视觉局部修改不因此启动完整选风格流程，小需求可合并已有审阅窗口。

### 2.2 存量设计按页面选择执行方式

先核对有效现状稿，区分已有可编辑页面、需要新增/补齐的整页、仅有截图或不可编辑的参考，在现有设计任务包中记录页面/Frame、改动、执行方式及理由。同一需求可混用下列方式，不要求所有页面使用同一工具。

| 页面情况 | 默认方式 | 执行要求 |
| --- | --- | --- |
| 已有可编辑 Figma 页面上的文案、控件、布局或状态迭代 | Computer Use 直接编辑图层/组件 | 复用原组件、变量和资产，保护已确认内容；不先让 Figma Agent 重画整页 |
| 新增全新页面或缺失整页 | Figma Agent 生成，再由 Computer Use 精修 | 输入已确认流程、页面职责及原系统组件/风格；仅生成授权的新页/Frame，不覆盖相邻既有页；确认实际结果后再直接精修 |
| 同时有旧页改动和新页 | 逐页混合执行 | 旧页直接编辑，新页生成后精修；涉及同一范围的生成与直接编辑串行，使用前一步实际结果 |
| 只有截图、只读稿或不可编辑内容 | 先明确制作目标与可用路线 | 截图可支持延续风格，但不能称其为可直接编辑的图层；不擅自改原文件权限或重建整个项目，按 `26` 绑定目标及 `18` 核对写入范围 |

已有页面即使改动较大，也先评估组件复用及直接编辑；若确需整体重设计，说明理由并依有效授权处理，不把局部需求扩大为改版。新增页面不等于新增品牌风格，有有效基线时不强制三套候选。直接编辑不依赖 Figma Agent 开通；生成新页缺少 Agent 时，只暂停相应生成，不阻断可独立完成的旧页精修。

生成与精修都须查看实际画面/导出，核对修改页、关键状态、相邻内容及共享组件影响；分别记录直接修改和 Agent 生成范围。无法定位或可靠编辑目标图层时先说明缺口，不以反复自然语言重生成冒充局部修改。

设计回传后取得本次有效 Frame 的 Dev Mode 链接，核实其可读性，通过 Figma MCP 读取同一版本的设计上下文、截图和素材；普通文件链接已能定位准确节点时，由 Agent 在现有授权内解析/定位，不重复要求用户复制同一链接。节点不明或当前工具/权限无法获取所需信息时，用 Question 请求具体 Frame/开发者链接或引导补齐能力，不能只看旧截图就称已完成还原。

核对设计稿版本、页面/状态覆盖及有效审阅或明确委托依据后，才由编码 Agent 还原对应范围的 Demo；引用实际组件、变量和资产，逐页比对布局、内容、样式和状态，并实际走通核心交互。设计缺失的新增页面、支付/异常等状态先回到 Figma 补齐或保留为未覆盖，不由 Codex 静默补画后称按稿还原。Figma 与 Demo 持续引用同一有效版本，后续设计变更同步回验。

开发者模式链接是定位输入，不保证原封不动还原，也不自动生成代码。分别记录“设计链接可读”“本次设计已形成并有审阅依据”“代码还原已验证”的证据与未覆盖范围；只读旧稿或仅完成本地 HTML 不满足本次 Figma 设计交付。

## 3. 产品原型最低合同

产品原型至少记录：入口与版本、覆盖的 SC/UC、核心页面或界面状态、关键数据与真实文案样例、主要操作、分支/失败/返回路径、未覆盖范围、验证类型和当前结论。静态截图只能作为辅助证据，不能单独满足“可操作”。

产品原型可以先于最终视觉设计，用于验证产品逻辑；已有 Figma 主稿时，先在 Figma 形成当前代表范围的流程设计，再还原可操作原型，不能把“尚非最终视觉”作为绕开主稿的理由。视觉设计不得删除未覆盖的动态状态或静默改写产品规则。

## 5. 页面交互规格

关键页面或状态复杂的模块创建 `DESIGN-<模块>-页面交互规格.md`。每个页面至少定义：页面目标与进入条件、固定布局和内容、字段/控件及校验、默认/加载/空/禁用/无权/失败/部分完成/结果未知状态、操作反馈、跳转/返回、响应式/无障碍、页面级验收。它解释“产品行为如何在页面中表达”，不替代任务包的范围和版本控制。

## 6. 回传与产品回审

设计方/Figma 回传后创建 `DESIGN-<模块>-回传与评审.md`，记录：任务包版本、实际 Figma 文件/页面/节点、截图或导出、已覆盖与未覆盖页面/状态、实际差异、验收项逐条结论、返工项、验证边界和下一责任方。记录代表页三套候选及选择依据、全页面展开版本、Computer Use 精修范围（未使用则说明）、设计还原 Demo 入口和版本。Codex 路线记录相应本地视觉与 Demo 证据，Figma 字段保持未产出。

多模块 Demo 再创建 `DESIGN-覆盖矩阵.md`：`SC/UC → 页面/状态 → 任务包版本 → Figma 证据 → 验收结论 → 缺口`。Figma 显示完成、提示词已发送或画面看起来合理都不能代替回审通过。

## 7. 设计就绪与回审门

- 产品原型就绪：存在真实可打开和操作的入口，覆盖与限制可定位；没有最终视觉稿不影响流程原型成立，但没有可操作证据时不得称默认产品交付完成。
- 设计就绪（D1）：当前范围的产品基线、流程与页面职责、关键场景、体验要求、可观察验收和写入范围已明确；已有原型作为输入，首次在 Figma 制作代表页不以已有编码 Demo 为前提；若需实际 Figma 写入，执行前核对卡中的目标、保护范围、授权和回传责任也必须明确；否则返回对应产品阶段或维持“任务包已准备、未执行”。
- 回审通过：高风险场景和状态有可定位证据；差异已修正或明确暂缓；设计验证与实现验证边界已说明。
- 有样式交付就绪：所有路线先满足 2.1 的风格选择或沿用依据；Figma 路线的设计链接可读、设计稿已确认、代码还原已验证分别有同版本证据。Codex 路线记录本地视觉产物、视觉选择依据与 Demo 验证，不要求 Figma 链接，但不能以代码生成或自检代替视觉选择，且需明示没有 Figma 稿。最终 Demo 的文案与关键交互仍按 `24` 专项复核，静态像素接近不等于交互正确。
- 已有 Figma 主稿的附加核对：本次变更已在 Figma 中形成，有准确 Frame/Dev Mode 定位、同版本设计上下文和 Demo 对照证据；缺项时不能以“参考过原稿”“本地 Demo 可操作”替代设计完成。明确改走本地设计时保留例外决定及交付差异，不追认此前业务确认。
- 发现业务冲突：回写 `01`/`04` 并标记受影响设计为待复核，不在 Figma 备注中形成新规则。
