# 产品判断能力索引

版本：v0.4｜用途：产品 Subagent 在当前问题中选择主责视角，并在 S6 做完整适用性筛查

这 48 项是判断视角和追溯索引，不是 48 个固定步骤、职位或文档章节。每个具体问题可涉及多项能力，应先判断当前最需要解决的产品问题；S6 再记录适用性、产品条目/场景证据和待验证缺口。

## P1 产品逻辑

| ID | 能力 | 关注问题 |
| --- | --- | --- |
| P1-1 | 产品价值及目标理解 | 产品为什么成立，用户和组织获得什么价值 |
| P1-2 | 领域理解与产品化转译 | 如何保真理解领域目标、因果、约束、例外并转成产品事实 |
| P1-3 | 产品对象理解与设计 | 产品中稳定存在什么对象，各自职责和边界是什么 |
| P1-4 | 对象关系设计 | 归属、引用、数量、关联和权限如何保持一致 |
| P1-5 | 状态体系设计 | 哪些状态真实存在，状态如何变化以及谁可改变 |
| P1-6 | 产品规则体系设计 | 条件、优先级、权限、冲突和结果如何推导一致 |
| P1-7 | 产品边界与异常设计 | 失败、例外、无权、并发和非目标范围如何处理 |
| P1-8 | 产品演进设计 | 规则、数据、历史和用户习惯变化后如何兼容演进 |

## P2 认知与心理引导

| ID | 能力 | 关注问题 |
| --- | --- | --- |
| P2-1 | 用户心智模型理解 | 用户将以什么既有经验理解产品对象和规律 |
| P2-2 | 认知负担控制 | 当前任务需要用户理解、记忆和选择多少内容 |
| P2-3 | 用户行为动机与引导 | 产品是否让用户在合适条件下愿意开始、继续或退出 |
| P2-4 | 用户预期与信任建立 | 承诺、范围、风险和实际能力是否可预测、可解释 |
| P2-5 | 用户认知迁移与习惯形成 | 用户能否将已学规律迁移到新对象或场景并形成自主使用 |
| P2-6 | 用户心理状态理解与调节 | 等待、错误、不确定和高压情境是否保持理解与掌控感 |

## P3 语义与表达

| ID | 能力 | 关注问题 |
| --- | --- | --- |
| P3-1 | 产品概念命名 | 对象名称是否准确、稳定、符合用户语境 |
| P3-2 | 动作语义设计 | 一个动作名称是否反映真实范围、后果与可逆性 |
| P3-3 | 状态语义表达 | 当前、历史、等待、成功、失败和未知能否被准确区分 |
| P3-4 | 复杂信息转译 | 复杂规则、数据和后果如何转成用户可判断的信息 |
| P3-5 | 产品语言一致性 | 页面、通知、帮助和不同端是否对同一事实使用同一语义 |
| P3-6 | 用户语境适配与表达吸引 | 语言是否适合角色、风险和场景，同时准确且易行动 |

## P4 空间与结构

| ID | 能力 | 关注问题 |
| --- | --- | --- |
| P4-1 | 产品空间与对象组织 | 用户如何理解对象归属及整体信息空间 |
| P4-2 | 分类分组与层级设计 | 分组和层级是否反映真实关系并支持扫描 |
| P4-3 | 空间排布与跨设备适配 | 同一对象在不同屏幕和设备中是否保持理解与可用 |
| P4-4 | 入口与可发现性设计 | 用户能否在需要时发现正确入口和下一步 |
| P4-5 | 导航、定位与返回设计 | 用户是否知道当前位置、来源和如何安全返回 |
| P4-6 | 任务路径与跨空间连接 | 跨页面、跨端、跨角色的任务能否连续且不丢上下文 |
| P4-7 | 结构适应与演进治理 | 新对象、增长和变化不会破坏原有定位和组织规律 |

## P5 交互与反馈

| ID | 能力 | 关注问题 |
| --- | --- | --- |
| P5-1 | 用户意图与操作映射判断 | 用户目标是否有合适、直接且可理解的操作 |
| P5-2 | 操作可发现性与可理解性判断 | 操作入口、条件和后果是否能被看见和理解 |
| P5-3 | 行为反馈闭环设计 | 提交、接收、实际结果和可回查凭据是否清楚闭环 |
| P5-4 | 用户控制、撤销与恢复 | 用户如何取消、修正、重试或在中断后继续 |
| P5-5 | 防误操作与风险交互设计 | 高风险操作是否核对对象与影响，低风险操作是否不过度打断 |
| P5-6 | 多路径与多输入方式一致性 | 同一对象和操作在不同入口、端和输入方式中是否同义 |
| P5-7 | 高频操作效率与熟练度设计 | 高频任务能否降低成本而不隐藏决定性事实或放大错误 |

## P6 过程与状态

| ID | 能力 | 关注问题 |
| --- | --- | --- |
| P6-1 | 生命周期与阶段设计 | 对象从开始到结束的阶段、责任和可用动作是否明确 |
| P6-2 | 状态变化过程可理解性设计 | 用户能否理解何时、为何、由谁发生了变化 |
| P6-3 | 等待与进度设计 | 等待时是否表达真实进展、可离开性和可行动项 |
| P6-4 | 中断、暂停与恢复设计 | 网络、离开、刷新和暂停后如何避免重复、丢失或误判 |
| P6-5 | 异步过程与结果到达设计 | 延迟结果、通知与对象当前状态如何一致并可回查 |
| P6-6 | 超时、失败与降级过程设计 | 失败、超时和部分成功如何如实表达并提供恢复路径 |
| P6-7 | 过程连续性与跨场景状态保持 | 换端、切换对象或长期任务后上下文如何延续 |

## P7 感知体验设计

| ID | 能力 | 关注问题 |
| --- | --- | --- |
| P7-1 | 感知目标定义 | 用户在关键时刻必须首先感知哪些事实、重点和风险 |
| P7-2 | 感知层级与重点判断 | 信息、操作和状态的视觉/感官优先级是否符合任务 |
| P7-3 | 感知一致性与秩序判断 | 同类信息和反馈是否形成稳定秩序，而非机械复制页面 |
| P7-4 | 感知心理影响判断 | 密度、强度、节奏和反馈是否支持信任、平静和决断 |
| P7-5 | 多感官反馈判断 | 视觉之外的声音、触觉、动态等通道是否必要、可控且不过载 |
| P7-6 | 感知可用性与包容性判断 | 颜色、文字、键盘、放大、阅读和输入是否覆盖实际能力差异 |
| P7-7 | 产品品味与品质判断 | 整体是否克制、协调、耐用并服务理解与使用 |

## S6 记录规则

每项写为以下三种之一，不以文档存在替代证据：

- `适用，已有产品判断/场景证据`：引用当前产品定义或代表任务，并标明仍需原型/实现验证之处。
- `适用，证据待补`：说明缺的是领域输入、设计覆盖、用户研究还是实现验证，指定回查责任。
- `当前不适用`：说明本期范围为什么不出现该问题；不能因为尚未设计或还未测试而填“不适用”。

对关键问题再做反事实检查：若只改文案、布局或视觉，问题仍存在，则应回到目标、对象、规则或过程机制修正。
