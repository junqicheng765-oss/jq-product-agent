# 代表任务与证据库

版本：v0.4｜用途：为复杂系统产品设计选择能揭示规则、体验和质量问题的代表任务，而非依赖品牌名或通用示例背书

## 使用方法

每个项目从下表选择与风险和范围相称的任务。每次任务推演都记录：角色与前提、触发事件、对象和状态、预期结果、不可接受结果、关联能力、证据类型和限制。以下是检查用例，不是“只要走过就证明通过”的测试脚本。

| 任务类型 | 要回答的产品问题 | 优先能力 | 可接受证据 | 常见误判 |
| --- | --- | --- | --- | --- |
| 目标任务 | 用户为什么现在需要完成这件事，完成后什么改变 | P1-1、P2-1/3 | 真实场景、目标、范围和反例；负责人确认 | 功能很多或指标高就等于有价值 |
| 领域规则转译 | 线下规则、例外和质量标准如何进入系统 | P1-2、P1-6/7 | 可追溯来源、冲突说明、台账和待核实项 | 把习惯、口头印象或技术默认写成规则 |
| 角色授权 | 谁可见、谁可改、谁可代表谁决定 | P1-4/6、P5-5、P6-7 | 角色权限表、失权/交接场景和真实授权来源 | 能看见就能编辑；管理员可代替所有人 |
| 创建与状态变化 | 发起动作改变哪个对象，何时实际成立 | P1-3/5、P5-1/3、P6-1/2 | 状态归属、成功凭据、历史记录和回查路径 | 点击成功或发出通知就算业务完成 |
| 多方审批/协作 | 提交、退回、撤回、改约、代理和超时如何处理 | P1-4/6/7、P2-4、P5-4、P6-5 | 各方独立状态、条件、异常和责任说明 | 只画顺序流程；把拒绝覆盖整体对象 |
| 共享与撤回 | 内容/数据共享给谁，范围改变后历史如何处理 | P1-4/7/8、P3-2/3、P5-5 | 对象范围、可见/下载/转发边界、撤回后果 | “全员可见”或“删除”没有具体范围 |
| 外部系统同步 | 谁是事实源，什么时候同步成功，乱序失败怎么办 | P1-2/6、P5-3、P6-5/6 | 系统边界表、成功凭据、降级、重试与人工补救 | API 返回或消息送达等于最终状态 |
| 异步生成/批处理 | 等待时用户知道什么，结果迟到或部分成功怎么办 | P2-6、P5-3/4、P6-3/4/5/6 | 可离开说明、查询入口、去重/乱序规则、失败恢复 | 无限加载、假进度或重复点击 |
| 高风险修改/删除 | 影响范围、不可逆后果和恢复责任是什么 | P1-7、P3-2、P5-4/5、P6-6 | 范围核对、真实可逆边界、历史和补救记录 | 用统一二次确认代替风险设计 |
| 跨端与深链继续 | 换端/跳转后如何保持同一对象、权限和上下文 | P4-3/5/6、P5-6、P6-7 | 稳定身份、返回规则、失权和过期链接情境 | 跳到首页或复制链接就算连续 |
| 高密度工作与查找 | 用户如何扫描、定位、比较和恢复工作位置 | P2-2、P4-1/2/4/5、P5-7 | 代表查询/筛选任务、空态/长内容/放大要求 | 只看正常列表截图 |
| 关键状态与风险感知 | 用户是否先注意到必须知道的事实 | P3-3、P7-1/2/3/6 | 状态文字、非颜色线索、多环境和多设置检查 | 红绿颜色或动画单独传达结果 |
| 长期演进与历史 | 新功能、规则或来源变化后旧事实如何解释 | P1-8、P4-7、P6-2/7、P7-3 | 版本、迁移、历史、替代和旧事件处理 | 新版直接覆盖历史且无说明 |

## 证据等级

| 证据 | 能支持的结论 | 不能越界的结论 |
| --- | --- | --- |
| 来源事实 | 领域规则、既有权限、系统能力或真实流程的当前已知情况 | 方案对用户一定有效 |
| 产品推演 | 对象、规则和流程在指定代表任务中能否自洽 | 真实用户能理解或系统已实现 |
| 原型/静态评审 | 结构、文字、状态和感知要求是否被表达 | 接口、并发、权限、性能真实成立 |
| 实现验证 | 指定环境、账号、数据和系统版本下的实际行为 | 所有用户/长期使用均已验证 |
| 用户观察 | 指定样本在指定情境的理解、行为或感受 | 代表全部人群或长期结果 |

证据不足时写明“缺什么、影响什么、由谁在何时补”。不能因为已有 Demo、设计稿或技术说明就把所有能力判为较强。

## 反事实检查

对每个重大问题问一次：如果只改文字、页面布局、颜色或动效，问题是否仍存在？仍存在时，回到 P1 的事实/规则、P2 的心理目标、P4 的结构、P5 的机制或 P6 的过程修正；不要把根因误归为视觉瑕疵。
