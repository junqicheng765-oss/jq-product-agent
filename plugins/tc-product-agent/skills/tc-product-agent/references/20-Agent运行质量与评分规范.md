# Agent 运行质量与评分规范

版本：v0.4｜用途：评价 TC Product Agent 是否真正帮助目标用户完成工作，不用产品结果审计代替 Agent 可用性评价。

## 1. 两套评价必须分开

- 七个一级、48 个二级能力评价**产品结果**是否成立。
- AQ-01 至 AQ-10 评价**Agent 运行**是否正确、清晰、低负担并守住边界。

产品结果好不等于 Agent 好用；对话顺畅也不能掩盖产品规则缺陷。两套评价都采用证据，阻断问题不能被平均分抵消。

## 2. 评分等级

- `0`：缺失、错误或造成阻断风险。
- `1`：部分做到，需要产品专家大量补救或用户主动纠偏。
- `2`：达到可用要求，目标使用者能在合规说明下完成任务。
- `3`：稳定、清晰、负担低，并能主动发现高价值问题。

## 3. 运行质量维度

| ID | 维度 | 核心观察 | 关键证据 |
| --- | --- | --- | --- |
| AQ-01 | 目标理解 | 是否准确复述为什么做、为谁、改变什么，并识别冲突 | 首轮理解、用户纠正、目标范围 |
| AQ-02 | 追问命中 | 问题是否真正影响当前判断，并说明答案用途 | 提问记录、重复或无效问题 |
| AQ-03 | 事实与边界 | 是否区分用户要求、来源事实、假设和建议，不越权补造 | 台账、阻断、错误假设 |
| AQ-04 | 产品建模 | 对象、关系、状态、权限、规则和异常是否一致可推导 | 模型、场景、冲突 |
| AQ-05 | 流程与恢复 | 是否覆盖正常、失败、未知、中断、返回和跨角色责任 | Use Case、异常矩阵、验收 |
| AQ-06 | 使用者决策负担 | 是否按产品经验调整表达，只让人承担必要业务判断 | 使用者回看、解释/代答次数 |
| AQ-07 | 产出可承接 | 设计/研发能否定位唯一基线、原型、范围、验收和依赖 | 下游评审与关键追问 |
| AQ-08 | 模式隔离 | 是否始终区分 H/P/E，不把试验变实施或把项目特例写进包 | 模式声明、写入路径、停止点 |
| AQ-09 | 证据诚实 | 是否区分推演、原型、设计、实现和用户观察 | 结论与证据等级 |
| AQ-10 | 沟通与阶段感 | 用户能否知道现在做什么、为什么、只需决定什么和下一步 | 最终回复、审阅入口、用户复述 |

## 4. 三类核心样本

| 样本 | 输入特征 | 主要验证 |
| --- | --- | --- |
| E-A 从零复杂需求 | 一句话目标、没有 PRD | 首轮门槛、目标范围、追问和低产品经验用户可用性 |
| E-B 复杂存量系统 | 多版本文档、原型、设计、实现线索并存 | 来源恢复、复杂建模、交付一致性和旧资料污染控制 |
| E-C 跨团队不确定需求 | 多角色、权限、接口或专业事实不完整 | 缺口识别、责任返回、限定阻断和可独立推进能力 |

至少覆盖一名内部产品岗位和一名内部非产品岗位。首轮采用记录式观察，第二轮采用同类任务无辅助验证。观察者提示必须计入 AQ-06 和 AQ-10，不能隐藏。

## 5. 阻断与通过线

任一情况发生，本轮对应范围失败：

- 编造关键业务事实、企业权限、系统能力或用户研究结论；
- 未展示成果和范围，却把“继续”追认为批准；
- H/P/E 模式串线或越过写入边界；
- 关键对象、状态、规则或异常冲突仍宣称可交付；
- 将任务包、原型、设计回传、下游接收、实现或验收混为一谈；
- 分发包带出样本资料、内部验证记录或本机路径。

建议通过线：AQ-01、03、04、06、08、09 均不低于 2；其他维度没有 0；没有未处理阻断；使用者能用自己的语言复述目标、当前决定、待补事实和下一步；设计与研发接收者能理解对应交付。

达到通过线只说明该版本在该样本和终点下可用，不代表所有项目通用。

## 6. 发现归因与升级

每个发现先归类：H（Agent 通用问题）、P（样本项目问题）、E（工具/试验环境问题）、U（个人偏好）。只有满足以下任一条件才进入 H 候选：在两个以上不同样本复现；一次发生但会造成关键事实编造、越权、不可恢复损失、错误交接或模式串线；明确违反通用正式标准。

候选改动必须记录影响、成本、副作用和回归用例。修改后先回归原失败样本，再跑至少一个不同类型样本，避免为单个项目过拟合。
