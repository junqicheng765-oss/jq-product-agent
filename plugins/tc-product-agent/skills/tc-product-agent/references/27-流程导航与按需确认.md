# 流程导航与按需确认

版本：v0.3｜用途：在 A–F 之间持续引导、核对阶段成果，并将人工介入限定为尚未解决的关键决定。产品设计启动或恢复、阶段切换、等待和收口时读取；咨询、维护与局部修改按约定终点裁剪。

## 1. 展示路线，持续交代位置

每次交付阶段成果、修订结果或发出审阅请求时，最终可见回复的第一行必须展示流程位置，放在成果摘要和链接之前。不能以已在过程播报、文件或上一轮展示为由省略。主 Agent 负责组合阶段 Skill 的结果并保留该行，阶段 Skill 单独使用时同样执行。

完整产品设计统一使用以下格式，替换全部占位内容：

```text
主线第 {n}/6 步「{阶段字母与名称}」｜当前：{本轮具体步骤}｜{真实状态}
```

A=1 问题与范围；B=2 方案与整体结构；C=3 场景与结构原型；D=4 代表性可操作链路；E=5 模块展开与体验收敛；F=6 详细规格与交接。编号是主线位置，不是完成百分比或确认次数；合并成果仍沿用这套编号，不按会议或回复次数重编。首次再给紧凑路线与约定终点，后续每次结果保留进度行即可。

阶段内需要多轮工作时，先将当前阶段的实际工作清单与版本记入既有工作状态；已有可恢复清单后，可在进度行增加 `阶段内第 {i}/{m} 步「{步骤名称}」`。同一阶段后续沿用这份清单，范围改变时说明调整原因。不得为了模仿其他 Agent 的展示而临时凑出固定七步。尚未拆分时写具体动作，不编造分母。示例：

```text
主线第 3/6 步「C 场景与结构原型」｜当前：页面结构修订｜待你确认关键结构
主线第 5/6 步「E 模块展开与体验收敛」｜当前：三套视觉方向比较｜待你选择风格
主线第 6/6 步「F 详细规格与交接」｜当前：交付材料与检查结果汇总｜本次任务完成
```

状态必须对应真实事实，可用制作中、已产出待复核、待你选择/确认、等你补充材料、工具受阻、本阶段完成、本次任务完成。只在存在未解决的关键决定时写待你确认；普通修正和自检不因此停下索要批准。完整交付条件未满足时不能使用“本次任务完成”。

咨询、维护和明确局部修改按本次终点显示 `任务「{任务名}」｜当前：{具体步骤}｜{真实状态}`，不为了状态行重跑 A–F；属于已启动产品主线的局部回查，保留主阶段并附 `回查：{阶段/事项}`。H/E 分别显示能力包迭代或受控试验及实际步骤，不套项目六步。跨阶段成果注明本次覆盖范围，分别列处理结论；存在阻断阶段时仍展示阻断位置，不能用已完成的后续工作掩盖它。历史成果的进度是产出时位置，不随主线推进批量改写。

每份新建或修订的阶段成果文件，在标题之后同步本次进度、版本和范围；合并文件按章节标明阶段，避免文件头声称全文处于某一个步骤。进度属于协作说明，只放在对话、成果说明和交付入口，不写进面向最终用户的 Demo 页面、按钮或产品文案。

阶段切换另外说明已完成哪些产物、哪些决定已有依据、现在进入哪里、下一项具体成果和负责人。每次结果的进度行不代替结尾的下一步或行动提示，也不要求再次展示全路线。

同一份 `product/00-工作状态.md` 承接下列内容，按项目复杂度用短段或表格记录，不另建进度台账：

- 本次任务与终点；A–F 各阶段当前范围、状态和成果入口/版本。
- 当前主阶段与必要回查、已完成产物、检查证据、有效确认或明确委托依据。
- 尚需人决定的具体问题、阻断范围、责任方和恢复条件；没有则写无。
- 下一动作、执行者和具体产物；当前是否需要人操作。

成果可以已产出但未检查；检查通过也不等于用户确认。明确不适用或用户裁剪的范围记录理由，不能为了凑全流程创建空产物或标成通过。

## 2. 什么时候真正需要人介入

阶段检查与人工批准分别处理。A–F 组织产出，不预设六次确认；阶段涉及的关键决定已有有效输入、确认或明确委托且未改变时，引用原依据，检查通过后继续。可将相关草稿合并展示，但不能依赖未决定的规则制作正式下游成果。

| 情况 | 动作 |
| --- | --- |
| 目标、首期范围、关键业务方案尚未明确，或新方案实质改变它们 | 给具体推荐、代价与范围，请有决定权的人判断；可合并 A/B |
| 新的核心流程、重要信息结构、可见结果尚未展示或未取得判断依据 | 展示骨架或可操作代表场景，请人判断实际使用是否符合预期；按风险合并 C/D，重大结构取舍在依赖制作前解决 |
| 新视觉方向或重要最终体验尚未确定 | 按 `15` 展示同内容真实候选/代表页并取得选择或明确委托；已有有效基线继续沿用 |
| 新增金额、权限、责任、不可逆后果、重大冲突或交付边界变化 | 提前提出这项决定与后果，只暂停依赖它的范围，不拖到固定阶段末尾 |
| 根据已确认规则展开 PRD、维护映射、修正文案、授权内局部精修、自检与复验 | Agent 完成并报告实质变化，不为文件生成或检查通过索要确认；发现新的业务含义再按上行处理 |
| 缺少来源事实、工具权限或必要配置 | 先在授权范围补证；需人提供材料、登录或绑定目标时给具体操作，不把事实或工具缺口包装成“请批准方案” |

“无偏好”“请建议”不自动等于委托最终决定；明确业务指令、已有效确认、范围清楚的明确委托可以直接作为依据。授权内同义改写、文案修错和表现精修不因换版本号重开确认。不能把新的业务规则当普通细节自行补齐。

需要人时，按下节实际弹出 Question；最终回复仍给一个主成果入口及版本、当前需要判断的少量具体问题、推荐与影响、确认范围和回复后动作。内部专业核对清单由 Agent 维护，通常聚焦 1–3 个关键决定；复杂内容分组，不把整份表交给使用者签字。

### 2.1 Question 弹出交互合同

- **触发**：只要需要使用者回答，包括基础信息补充、现状链接/配置、业务取舍、方案确认、代表体验审阅、风格选择，以及希望用户回复“按建议继续”，都实际调用原生 Question。普通进展、已完成结果、自检和已有有效确认不触发新问题，不按每一步新增审批。
- **工具**：先用当前宿主实际提供的工具；Codex 有 `request_user_input_async` 时优先使用，异步问题发出后可继续独立工作。仅有 `request_user_input` 时遵守其模式及用途限制，不为弹窗擅自切换模式。没有可调用工具或调用失败时明确说明，降级为同样清楚的文本问题；Markdown 选项、HTML、文件更新不能冒充已发出的原生 Question。
- **内容**：每题自包含，说明此次版本、审阅/决定范围、推荐及主要影响、回答后将做什么；相关成果有链接时放入问题及最终回复。根据工具容量把相关问题分组，通常每组 1–3 个，不把多个独立决定塞进一个“全部同意”。
- **选项**：有可判断建议时提供“按建议继续”，另给“需要调整”等有意义选择；选“需要调整”但未给内容时只补问调整点。风格比较用具体方案名称。缺少事实、链接或材料时用自由文本或具体输入指引，不用“按建议”代替事实。保留工具支持的自定义回答；自由输入的明确决定同样有效，不要求必须点击。
- **等待**：预选、未提交、关闭、超时、已读或只回答部分问题，都不算接受建议。按题记录真实回答和范围，未答项维持未定，仅暂停依赖它的动作。用户从其他消息已明确回答时直接合并，不为获得一次点击重复确认；多版本或互斥选项仍不清楚时只补一个具体 Question。
- **审阅衔接**：成果先形成并可打开，再弹 Question。需要登录、上传文件或工具外操作时，问题说明真实操作入口和完成后如何通知，不要求在文本框填凭据或假装支持文件上传。最终可见回复说明正在等哪一项回答与之后动作，不要求在弹窗之外再回复一次固定口令。

## 3. 阶段出口由 Agent 核对

切换阶段及最终收口前，复用 `07` 的质量门和 `23` 的产物模板，针对本次约定范围核对：

1. **产物**：必要内容确已生成，可定位和打开；承诺可操作的原型确已操作，任务包和截图不冒充它。
2. **覆盖**：目标、场景、页面/状态及验收在当前阶段需要的覆盖是否足够；未完成项及理由可定位。
3. **质量**：适用检查有真实结论与证据；Demo 文案与交互按 `24`，未做的验证不报通过。
4. **决定**：所依赖的关键决定有有效来源、确认或明确委托；普通推导细节与新的业务决定分开。
5. **版本和衔接**：下一阶段引用的是有效版本，引用与受影响范围无冲突；最终交接再按 `07` 做断链、关键需求验收和过期版本检查。

核对结论与证据记入既有工作状态、评审或交付说明，不另建同内容的矩阵。区分可推进、待补检查/产物、待人决定、受外部条件阻断，以及不适用/明确裁剪；每项缺口说明影响与下一动作。能在本轮补齐的授权工作先补齐，只回验受影响范围。检查条件全部适用，不等于每一步全量跑能力模型或新增测试脚本。

全部阶段都要能找到对应产物与处理结论，允许合并文件和审阅。某个阶段结束不能自动使其余阶段完成；约定范围有必要成果缺失或阻断未处理时，不能宣布默认完整交付完成。用户决定缩小交付范围时记录变化，不以默默省略代替裁剪。

## 4. 连续执行与结束回复

- 已授权、输入足够、无需新决定的工作，在本轮继续到真实人审点、外部阻断或约定终点；不让使用者反复说“继续”才能串起内部步骤。
- 执行中的“下一步制作原型”是过程播报，随后实际制作；不能以这句话结束回复并暗示后台会继续。
- 真正等待时说明在等谁、等什么、已完成什么、回复后进入哪里；有独立工作先完成。没有已启动的运行机制，不声称正在等待未调用的 Agent 或会自动跟进。
- 最终回复明确本次是阶段成果待判断、受阻，还是约定任务已完成。完成时给交付入口、范围、各类产物/检查真实状态和剩余限制；未约定的实际发送、接收、实现和部署不算已完成，也不列成擅自扩大的欠项。

结束前检查：使用者仅看本条回复，能否知道现在在哪、是否结束、自己要不要行动、下一步由谁产出什么？需要追问这些基本问题时，先补齐导航或继续实际执行。
