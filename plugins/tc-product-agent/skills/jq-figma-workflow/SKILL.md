# JQ Figma 设计执行与 Demo 还原

本 Skill 随完整 JQ Product Agent Plugin 提供，依赖同包合同，不依赖作者电脑上的全局 Figma 工作流、固定应用路径或专用脚本。它提供执行方法，不安装 Figma 服务、账号权益、MCP 服务器或宿主 GUI 操作底层工具，也不自动启用子 Agent。**合同宿主无关**；Codex、Cursor 等仅为示例宿主，工具名按实际环境映射。

## 输入与职责

**人设计师是视觉主责。** 主产品 Agent 负责当前事实、业务规则、体验/视觉判断、任务包和验收要求。本 Skill 在明确授权下负责 Agent 侧实际执行、采集设计与实现证据、核验差异并返回；发现业务含义改变时返回产品主线，不在执行中自行决定。Agent 代写须保留可被人核验的节点与画面回传。

执行输入沿用 [设计任务包](../tc-product-agent/references/15-设计交付与Figma回传规范.md#4-设计任务包) 的短清单或等价结构，不要求使用者手填 JSON，也不另建一套规则。至少能定位：

- 任务包 ID/版本、产品输入及本次范围、SC/UC/规则与验收引用。
- 用户指定文件、页面/Frame，允许的动作和受保护内容。
- 当前组件/变量/原始资产、页面短清单要求；Agent 执行时可含提示词。
- 当前工具能力证据、执行分流、结果回传和核验要求。

缺专业内容由主 Agent 从当前项目补齐；仅缺使用者才能决定的事实、文件或权限时，按 [Question 合同](../tc-product-agent/references/27-流程导航与按需确认.md#21-question-弹出交互合同) 实际弹出**宿主可用的原生提问工具**。不要让使用者判断内部技术清单或重复批准已有范围。人设计师持短清单即可开工，不因本 Skill 工具未就绪而阻断。

## 1. 初始化与恢复

读取 [设计能力初始化与复用](../tc-product-agent/references/26-设计能力初始化与复用.md)，复用本任务配置及有效授权。已有本产品 Figma 设计稿即默认作为设计主稿；只有竞品/灵感参考不触发该默认。首次制作前在对话展示实际路线、目标、可用能力及必要缺项。

按本次动作逐项验证，不把全部工具当作所有任务的共同前提：

| 本次动作 | 实际所需能力 | 验证与缺项恢复 |
| --- | --- | --- |
| 读取现状、定位设计 | 可用的 Figma MCP（或等价读取）及目标读取权限 | 读取本次节点的元数据/上下文或截图；失败时区分认证、文件权限和节点问题，用原生提问引导在官方入口完成连接或登录 |
| 旧页直接精修 | 人设计师手工，或宿主 GUI 操作 + 目标编辑权限及可定位图层 | 核对应用、文件、页面与选区，先观察不写入；缺 Agent 生成能力不阻断该动作；人不依赖 GUI 自动化 |
| 新整页生成 | 人设计师手工，或当前可用 Figma Agent/插件入口、账号能力、编辑权限 | 用真实界面或可用工具核对；自动化路线须能操作实际入口，不能从 MCP 已连接推定生成可用 |
| 设计到 Demo 还原 | 准确 Frame/节点与有效设计；需要时 MCP 设计上下文/截图/素材、本地代码及浏览器验证 | 回传人审最低不强制 Dev Mode；代码还原缺项时仅准备任务与证据，不报已还原 |

具体安装、配置入口或账号权益按当前宿主和官方说明核实后引导，不编造命令、套餐、按钮或权限。账号登录和购买由使用者完成，不索取或保存密码、令牌、Cookie。已有普通文件/节点链接可准确定位时直接复用，不为了 Dev Mode 文案再要求复制一遍。

没有底层工具时，说明本会话无法直接操作哪一部分，通过 Question 引导配置；使用者也可明确选择由协作方在同一 Figma 完成并回传准确节点。尚未交给执行者时不称正在等待回传。已有主稿不能因缺工具自动改成本地独立设计；例外须有使用者明确决定。

## 2. 在 Figma 执行

写入前按 [执行前核对卡](../tc-product-agent/references/18-Figma执行前核对卡.md) 引用任务包、有效授权、唯一目标和保护范围。无目标时请使用者指定归属并提供文件，不自行建团队、项目或文件；已有授权范围直接沿用。

执行前必须已有同包 `$design-thinking-os` 写出的 `design-decisions.md`（含 D1–D9 状态、第一眼对象位置、逐组件材质句子、「现在才允许做页面」）。没有这份文件，本 Skill 不得生成或精修页面。读取 [生成与直接精修手册](references/figma-execution.md)，并按决定文件执行，不要在这里重新选风格或跳过真图库。旧页直接编辑；新整页按决定文件锁定的风格参数生成后精修；同一区域生成与精修串行。人物头像/图标/3D/插画走 IconScout；真实摄影先走 Real Image Library（`IM`）；无匹配或必须虚构才原位生图。回传前执行 [QA0 三大维度验收](../design-thinking-os/methods-close.md)（用户可用性 × 审美与品位 × 设计标准）。

D 可先用灰框加文字的流程骨架验证链路。进入正式视觉与有样式交付前，必须已有 `design-decisions.md`，再形成代表链路所需的 Figma 页面/状态并还原。E 扩展时先更新决定文件与主稿，再同步 Demo。不为检验工具擅自生成页面；不以本地 HTML 冒充 Figma 设计完成。

## 3. 设计回传与 Demo 还原

设计形成后核对本次页面、状态、组件与相邻影响，返回准确文件/Frame、版本和实际截图等**最低回传证据**，不以 Agent 宣称完成代替画面核验。需要人判断的核心体验或视觉取舍由主 Agent 弹原生提问，已有有效决定不重复确认。

需要代码还原时再读取 [Dev Mode 到 Demo 手册](references/design-to-demo.md)。使用同版本的准确节点、设计上下文、截图及原始素材还原已有代码，复用项目组件；设计缺失先回主稿补齐。代码还原不包括生产接口、部署或未授权的系统实现。

## 4. 返回与恢复

结果并入现有设计回传、Demo 说明和工作状态，不另建重复台账。每次执行记录任务包版本、本次执行标识/步骤、实际目标、动作、结果节点/证据、核验结论、差异和下一责任方；提交后结果不明时先查原结果，不重复发送。返工保留原证据，仅处理差异范围。

分别报告：工具/目标可用、本次 Figma 设计已形成、审阅依据、Demo 还原与动态核验。部分完成、结果未知或未核验如实保留，不能合并成一句“设计交付完成”。最终回复沿用 [流程导航](../tc-product-agent/references/27-流程导航与按需确认.md)，保留主线位置和具体下一动作，进度不进入用户 Demo 文案。
