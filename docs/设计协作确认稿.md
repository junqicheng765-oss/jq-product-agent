## 2. 真实工作流步骤（相对 As-Is）

### 2.1 As-Is 主链

```text
A–C 产品基线/结构
  → 设计任务包（+ 必要时 18 核对卡）
  → 路线：有本产品 Figma 主稿 → Figma 生成/精修；否则明确例外 → Codex 本地视觉
  → 设计回传与产品回审
  → Dev Mode / 本地还原有样式 Demo
  → handoff/rd 研发交接
```

阶段细节（As-Is）：
- **C**：可有低成本结构骨架；有主稿时实际骨架优先在 Figma。
- **D**：代表链路；视觉可为流程验证用临时方向；有主稿则先 Figma 再还原 Demo。
- **E**：扩展模块/状态；无基线时三套同页风格候选；选定后展开正式视觉并还原。
- **F**：引用设计证据做交接；三态分开：链接可读 / 稿已确认 / Demo 还原已验证。

### 3.4 短清单模板（提案：替换冗长页面块给人设计师）

```markdown
### <页面ID> <页面名>｜<主状态>
- 用户要完成：<一句话>
- 必须看见：<字段/对象/风险点>
- 主操作 → 结果：<动作 → 反馈/去向>
- 必做异常：<空/错/无权…中与本次有关的>
- 关联：SC/UC / AC
- Figma：<目标 Frame 或「待建」>
```

长版页面字段（进入条件、全状态枚举等）保留在「页面交互规格」或产品 PRD，不强制塞进给人看的任务包首页。

## 5. 争议清单（必须拍板）

| ID | 问题 | As-Is | 设计师侧提案 | 她侧决议 |
| --- | --- | --- | --- | --- |
| Q1 | 谁画主稿？ | Agent 可在授权下生成/精修；人也可 | **人设计师主责视觉**；Agent 代写须逐次授权与可核验回传；旧页优先精修、新页可生成 |  |
| Q2 | D 是否必须先 Figma？ | 有主稿时临时视觉也不豁免，须先 Figma 再 Demo | **D 允许低中保真流程原型先验证；正式视觉/有样式交付前回 Figma** |  |
| Q3 | 三套风格？ | 新产品无基线强制三套同页候选 | **有 DS/品牌则默认沿用；无 DS 且需选气质才强制三套；改品牌单独授权** |  |
| Q4 | 任务包粒度？ | 完整 Markdown 长模板 | **对人：短清单；对 Agent：可保留长模板或由短清单生成提示词** |  |
| Q5 | 回传最低证据？ | 节点+截图+覆盖+验收；多模块矩阵；Dev Mode 用于还原 | **最低：准确节点链接 + 关键页截图 + 覆盖/缺口 + 验收结论。** Dev Mode/MCP 仅在要做代码还原时必须；单模块不强制独立覆盖矩阵文件 |  |
| Q6 | Cursor vs Codex？ | 文案偏 Codex（Question API、Computer Use） | **合同宿主无关**；执行手册写「宿主原生提问 / 可用的 GUI 操作 / Figma MCP」，示例可提 Codex 但不写成唯一依赖 |  |
